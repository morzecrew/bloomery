## The plan, as far as it got

Files the phase would touch, one line each:

- `src/bloomery/imports/__init__.py`, `metricflow.py` — new package: manifest text in, relationship values out. Pure, so the CLI keeps the reads and writes and compilation stays a function of committed specs (RFC 0003).
- `pyproject.toml` — one new layer in the import-linter contract for that package.
- `src/bloomery/cli/__init__.py` — the `import` subcommand, its parser and its handler.
- `tests/unit/test_imports/` — one hand-authored manifest per refusal row of §5.2, plus the `natural`-imports-nothing case.
- `tests/fixtures/` — a fixture whose relationship carries `imported_from:`, so §6's end-to-end test reaches `ASSUMED` from a project rather than from the direct `weak_bases` call P1 left behind.
- `pages/docs/how-to/` — the import/overlay/`check` adoption page §7 asks for.
- `rfcs/`, `logs/` — retirement of 0070 and 0044 together, and this log.

Governed by: §5.1 and row 5 (MetricFlow, not dbt) for the format; row 1 and P1's landed
shape for where the provenance is read; row 3 for keeping it out of the IR; row 4 for the
conflict predicate.

Two of the entries above are what stopped the plan, and the count is worth stating
accurately rather than rounded up to the readiness gate's three. The name-scheme question
is decidable by an executor and is recorded as decided, not as a blocker. What halts this
is that two measurements say the command as specified does not work: it writes a document
no project can load, and it matches semantic models to entities by a rule that fails on the
ordinary case. D6 is void either way — it asks which of two layouts the unloadable document
takes.

A `LOCKED` row is not what is being contradicted here, which is why the entries are graded
`UNLISTED`. The halt is not about grade strength: it is that every remaining choice in the
phase — the name scheme, the conflict predicate's inputs, the fixture, the docs page — is
downstream of what the command produces, and picking that from inside the task would be
writing the design rather than executing it.

## Self-audit — RFC 0070 P2, 2026-09-14

Whole branch: 3 commits, 19 files, roughly 1,900 lines added and 870 removed, of which the
removals are the three retired documents. Scope from `audit_scope.py scope --base main`.

**Four findings, all fixed on the branch. No open ones.**

**1. The order test could not fail (sabotage).** `test_the_element_order_…` permuted both
the models and the elements of a manifest in which only one model carried a `foreign`
element — so every edge came from one iteration and the model sort was unreachable. Removing
`sorted(parsed.semantic_models, …)` left the suite green. Rewritten with two source models,
one of them carrying two foreign elements, so both axes are exercised; the rewrite then let
the *element* sort survive until that was restored too, which is the same mistake twice and
the reason the assertion now counts the edges it is comparing.

**2. `natural` was never tested as a target (sabotage).** The positive case — a `natural`
element alongside a valid pair, and the pair still imports — passes whether or not `natural`
is admitted on the to-side, because nothing pointed at it. Replacing the `_UNIQUE_SIDE`
membership test with "anything that is not foreign" left the suite green. Now a `foreign`
element whose only same-named declarer is `natural` is asserted to refuse.

**3. The stop between the mapping and naming stages was untested (sabotage).** Removing the
first `if errors: raise` left everything green, and it is not equivalent: measured, a
manifest with both an unresolvable element and a would-be name collision reports one error
with the stop and two without. The second is a consequence of the half-resolved edge set
rather than a second problem — fixing the first changes the edge set — so the stop is
load-bearing and now has a test that names why.

**4. `import` accepted a `--catalog` it could not use.** `_add_spec_directory` adds the flag
to every command that takes a spec directory; this one reads relationships, and a catalog
carries canonical field definitions. It parsed, loaded a file, and changed nothing
observable. The positional is now added directly and the absence is pinned by a test, since
nothing else would notice the flag coming back.

**Sabotage sweep: 21 mutants, 21 killed, 0 survived, 0 skipped.** Apparatus checked rather
than assumed — the pattern count is asserted before each mutation so a stale pattern reports
`SKIP` instead of a kill, none did, the source is restored from the string read rather than
by `git checkout`, and the baseline is green (239 tests over the four affected files).

Coverage of `src/bloomery/imports.py` is 113/113 statements and 44/44 branches. Recorded
after the sweep rather than as the result, because a covered line that survives sabotage is
the finding.

**What was checked and found sound:** no golden moved (`git diff main..HEAD -- tests/golden/`
is empty), which is what D3 claims; the docs build is clean under `--strict`; no link to any
of the three retired documents remains outside `RETIRED.md`; each of the three is readable
at `c771ff0`, the commit their rows name.

**What remains uncertain.** Every manifest in the suite is hand-authored — §3 of the retired
document says why one cannot be round-tripped out of bloomery's own emitter — so nothing
here has met a manifest a real MetricFlow project produced. The mapping is exact against the
schema and untested against the wild. The second thing is narrower: `--entity` refuses a
mapping naming no model in the artifact, which is right for a typo and may be wrong for a
standing map pointed at a partial manifest. Nothing has asked for that yet.

## Review round 1 — 2026-09-15

Seven findings, every one reproduced red before it was fixed. Six are defects in this
branch; the seventh is a sentence that falsified itself.

**An `expr` ending in a newline passed as a bare column name.** `IDENTIFIER_PATTERN` is
anchored at both ends and `$` also matches *before* a final newline, so
`re.match(IDENTIFIER_PATTERN, "order_id\n")` is truthy and the column reached `via` with a
newline in it. Read with `fullmatch` now; the constant keeps its anchors, because it is
shared and pydantic reads it elsewhere.

**A mapping target was only checked where an edge happened to reach it.** `_entity` runs
inside `_edges_of`, so a model carrying no `foreign` element never had its mapping looked at:
`--entity customers=nonesuch` was accepted in full whenever `customers` was only ever a
target. Both halves of every mapping are checked up front now.

**Two models stating one join produced two relationships of one name.** Two semantic models
mapping to one entity and stating the same join are one relationship twice; `_generated_names`
widened both to the same string, and `render` printed a duplicate that `resolve` refuses by
name. Collapsed before naming, on §5.4's rule that agreement is not a contradiction.

**A join column was checked for being an identifier and not for existing.** An artifact
spelling `customer_id` against an entity declaring `customer_key` produced a block that
parsed, pasted cleanly and refused at resolution — with a message about the author's own
spec rather than about the artifact. The importer makes the same check `resolve` does,
earlier. This is the finding that mattered most: every manifest in the suite had been
written with invented column names, so nothing in it had ever pasted into a project that
could resolve. They now use columns `ecom_basic` declares, which is why that commit touches
almost every case.

**A malformed `--entity` lost to a broken spec.** `_import` read the files before parsing
the flags, so a bad flag against an unparseable project exited 1 rather than 2 — telling the
caller their project was wrong when the invocation was.

**The how-to said a generated name could be renamed freely.** It said "nothing downstream
depends on the generated spelling", which this branch's own end-to-end test disproves: it
had to repoint the mart's `flatten:` step at the generated name. The page now says the name
is a key and what else refers to one.

**Two different joins could widen to one generated name.** Read as a duplicate of the
finding above and measured separately, which is what stopped it being closed with it: the
widening appends `{from_column}_{to_column}`, so `{order_id: x}` and `{order: id_x}` — two
different joins between one pair of entities — build the same string. No separator fixes it,
because every character a bare column name may hold is one it may also hold in the middle,
and a rarer separator only moves the collision to whoever had no reason to expect it. The
generated names are checked against each other now and a repeat refuses, naming both joins.

**`INDEX.md` claimed something its own sentence falsified.** "The only remaining mention of
0065 anywhere in this directory" appeared in a paragraph that mentions 0065. Reworded to
what was measured — no live RFC argued in its vocabulary, and the one that named it did so
in a prose citation — and the paragraph now says that it names it too.

**Drift count: 0.**

Worth recording rather than leaving as a clean round: **the sweep on this branch was green

was the importer agreeing with a fiction. A reviewer found it by reading the code against
the project rather than against the tests.

The rule that generalises: a sweep proves the tests are sensitive to the code, never that
the inputs could occur. Where a component's output is meant to be *fed back* into the system
it was read from, the test that matters is the round trip on real inputs, and mutation
coverage over hand-built ones will not stand in for it.
