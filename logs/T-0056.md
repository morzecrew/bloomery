## The plan, as far as it got

Files the phase would touch, one line each:

- `src/bloomery/imports/__init__.py`, `metricflow.py` — new package: manifest text in, relationship values out. Pure, so the CLI keeps the reads and writes and compilation stays a function of committed specs (RFC 0003).
- `pyproject.toml` — one new layer in the import-linter contract for that package.
- `src/bloomery/cli/__init__.py` — the `import` subcommand, its parser and its handler.
- `tests/unit/test_imports/` — one hand-authored manifest per refusal row of §5.2, plus the `natural`-imports-nothing case.
- `tests/fixtures/` — a fixture whose relationship carries `imported_from:`, so §6's end-to-end test reaches `ASSUMED` from a project rather than from the direct `weak_bases` call P1 left behind.
- `pages/docs/how-to/` — the import/overlay/`check` adoption page §7 asks for.
- `rfcs/`, `logs/` — retirement of 0070 and 0044 together, and this log.

Governed by: §5.1 and row 5 (MetricFlow, not dbt) for the format; row 1 and P1's landed
shape for where the provenance is read; row 3 for keeping it out of the IR; row 4 for the
conflict predicate.

Two of the entries above are what stopped the plan, and the count is worth stating
accurately rather than rounded up to the readiness gate's three. The name-scheme question
is decidable by an executor and is recorded as decided, not as a blocker. What halts this
is that two measurements say the command as specified does not work: it writes a document
no project can load, and it matches semantic models to entities by a rule that fails on the
ordinary case. D6 is void either way — it asks which of two layouts the unloadable document
takes.

A `LOCKED` row is not what is being contradicted here, which is why the entries are graded
`UNLISTED`. The halt is not about grade strength: it is that every remaining choice in the
phase — the name scheme, the conflict predicate's inputs, the fixture, the docs page — is
downstream of what the command produces, and picking that from inside the task would be
writing the design rather than executing it.
