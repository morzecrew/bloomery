## D-116 — what P1 leaves unbuilt, stated before the code

```divergence
decision: RFC 0040 §11 — P1 represents existing trivially safe requests as SemanticPlan with no capability expansion
grade: UNLISTED
class: spec-gap
at: 2026-09-05T20:05:00Z
attempt: 1
claim: §11 names what P1 does and the document as a whole names much that it does not, and the boundary between them is nowhere written; P1 builds Scan/Filter/Aggregate/Project over one already-flattened mart and does not build §4's PreservingJoin or ConvertUnit, §5's cross-entity planning rule, or §6's target-refusal contract for targets that do not exist. A consequence worth stating with it: a pre-joined mart has no multiplicity-changing node, so D2's invariant holds over an empty set at P1 and is satisfied vacuously rather than exercised
evidence: `grep -n "P1 — plan IR only" -A8 rfcs/0040-safe-rollup-planner.md` -> `P1 — plan IR only. Represent existing trivially safe requests as SemanticPlan; no capability expansion.`
action: decided
proposal: §11 gains a sentence per phase naming what that phase does *not* carry, and §10 D2 gains a note that its invariant is vacuous until P2 introduces the first multiplicity-changing node. Written here before the code because the previous two executions each narrowed scope for good reasons and recorded nothing, and both times the self-audit had to raise it — naming the deliverable is not naming the omission
```

## D-117 — a group-by grain is not a grain, and does not need to be

```divergence
decision: RFC 0040 §5 — Aggregate(input_grain=Order, output_grain=CustomerCountry)
grade: UNLISTED
class: spec-gap
at: 2026-09-05T20:10:00Z
attempt: 1
claim: §5's accepted example names an output grain of `CustomerCountry`, and RFC 0037's GrainRef is key identity — `country` is not part of `customer`'s key, so `can_roll_up` refuses that target as `unknown_grain`. Taken literally the example needs vocabulary RFC 0037 does not have; taken as RFC 0039 §7 renders the same argument, it needs none: prove the rollup to the dimension's *key* grain and the column is determined by that key, which is step 3 of that worked example
evidence: `uv run python -c "...can_roll_up(grain('order','order_id'), grain('customer','country'), CORPUS)"` -> `RollupRefusal unknown_grain`, while the key-grain question returns `RollupProof` and `ColumnRef('customer','country')` is in its closure
action: decided
proposal: §5's `output_grain` is a *display* name for "the target key grain, projected to these columns", and §4's Aggregate carries the key grain plus the projected columns rather than a grain that does not exist. No new vocabulary; RFC 0037's GrainRef stays identity-only, which is what D1 there locks
```

## D-118 — `SemanticPlan` sits beside `QueryPlan`, not under or instead of it

```divergence
decision: RFC 0040 D7 — whether SemanticPlan lowers to the existing QueryPlan, replaces it, or sits beside it
grade: OPEN
class: discovery
at: 2026-09-05T20:15:00Z
attempt: 1
claim: the three shapes are not equally available at P1. `QueryPlan` is what `bloomery plan` and `bloomery explain` print and what every golden pins, so replacing it changes an outward surface — and D5 makes P1 a re-expression with no capability change precisely so the parity suite can tell a regression from an intended widening. Bundling an output change into that phase costs the suite its only reference point
evidence: src/bloomery/planner/result.py:117-130
action: decided
proposal: D7 closes as "beside, at P1": `QueryPlan` gains a `semantic` field carrying the plan, and nothing that prints today prints differently. Whether it later lowers to `QueryPlan` or replaces it is a P2+ question with the parity suite already in place to answer it — which is the thing P1 was supposed to produce
```

## D-119 — parity pins the outcome, never the wording

```divergence
decision: RFC 0040 D8 — whether refusals for already-refused requests may change wording
grade: OPEN
class: discovery
at: 2026-09-05T20:18:00Z
attempt: 1
claim: §8 asks that "every request refused before a phase is still refused after it", which is a claim about outcome; pinning text as well would freeze `UnreachableAtGrain`'s wording, which §9 already calls worse than a refutation would be. A suite that fails when a message improves is one people learn to update without reading, and it stops being evidence of anything
evidence: `grep -n "still refused after it" rfcs/0040-safe-rollup-planner.md` -> `a parity suite asserting that every request refused before a phase is still refused after it, except where a named proof rule deliberately converts a class`
action: decided
proposal: D8 closes as "outcome, and the error class — never the text". The parity suite asserts that a request refused before is refused after and with the same exception class; message goldens stay where they are, as goldens, and move deliberately when a message is improved
```
