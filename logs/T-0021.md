## Findings — self-audit, 2026-09-05

Scope: the whole branch, 4 commits, 12 files, +989/−9 — source, tests, the determinism
guard, the package surface and this log. Gates re-run after every fix.

### 1 — nothing consumes the plan, and the module said the opposite

`grep -rn "\.semantic\b" src/bloomery/` returns exactly one line: the construction site.
MetricFlow still plans from the request, so the plan is built beside the SQL and read by
nobody — which is correct for P1 and is **not** what the module docstring implied when it
said §6 asks for "bloomery decides, targets lower" and "this is the value it decides into".
A reader would reasonably take a plan's presence as evidence it produced the query beside it.

Now stated, and pinned: a test asserts structurally that no module reads the plan, since
being unread is precisely why P1 changes nothing and there is therefore no behaviour to
observe. Verified red by adding a reader.

### 2 — an empty plan constructed and reported itself valid

`SemanticPlan(())` passed `check`, because an empty sequence satisfies "every multiplying
node carries a proof" perfectly. A plan with no nodes computes nothing, so the empty case is
decided now rather than inherited from the reduction — the same shape as `Proof.closed`
returning `True` for a proof resting on no facts, one branch earlier.

### 3 — a field comment describing a case that cannot arise

`Aggregate.proof` was documented as `None` "only where the input and output grain are the
same relation and nothing was rolled up" — which is every P1 aggregate, all of which do
carry a proof. It now says what is true: optional on the type, always present on what the
builder produces.

### What I would still distrust

- **The parity suite's refusal side is thin where it matters most.** 76 of its 108 refusals
  are one fixture failing wholesale, so what varies by request shape is 32 across three
  classes. Strong against a phase that changes an outcome; weak against one that changes a
  reason, which is what P2 will mostly do.
- **D2 is vacuous and D4 unenforceable at P1**, both by construction rather than by
  oversight, and both now carry canaries that fail when P2 makes them real.
- **R008 is asserted, not derived.** It cites the mart contract that `check_grain` enforces
  at compile time, and nothing here re-checks it: if that guardrail were wrong, the proof
  would faithfully report the wrong thing.

## Findings — review round, 2026-09-05

Six defects, all in code this branch wrote, all fixed here. Two of them are the same defect
in different clothes and worth naming as one: **a check that reads a field for its existence
rather than its content.** `check` accepted any non-`None` proof; the locator accepted any
line containing a substring. Both were green, and both were green for reasons unrelated to
what they claimed.

### Correction to finding 1 of the self-audit above

That finding's evidence line reads: `grep -rn "\.semantic\b" src/bloomery/` "returns exactly
one line: the construction site". **Both halves are false.** The command returns 19 lines,
every one of them a module path in an import or a docstring reference, and the construction
site — `semantic=semantic_plan.build(...)` — is a keyword argument that the pattern cannot
match. The underlying claim is true and now rests on something that checks it: no
`ast.Attribute` named `semantic` exists anywhere under `src/bloomery/`.

This is the second execution in a row where a quoted command output was typed from memory
of what it should say rather than pasted from what it did say. The first (D-110, RFC 0039)
was caught by the same review surface. Appended rather than corrected in place, per this
log's own rule.

### The rest

- **A row policy and a metric's own filter never reached the plan** (D-125), so the plan's
  account of what a query restricts was, for those requests, false in the direction that
  matters: broader.
- **A derived metric produced a plan asserting the ratio was a stored mart measure**
  (D-123) — a false fact inside a proof, which is the defect class this whole sequence
  exists to make impossible.
- **The parity suite compared class totals** (D-126), so its central claim survived a
  swapped pair. Its baseline now comes from the merge base and compares per request.
- **`Filter` sorted a tuple that was already deterministic** (D-122) and, in doing so, broke
  the equality its own test asserted — which the no-filter case could never see.

### What I would still distrust, revised

- The parity suite's refusal side is still thin in the way the previous section recorded;
  keying and per-request comparison make it precise, not broader.
- `applied_predicates` renders a metric's restriction through `Predicate`/`Op` rather than
  through the emitter's own path. The strings agree today because both read the same IR, and
  nothing asserts they must — a third renderer of the same clause is a divergence waiting for
  a reason.

### The sweep's own survivor

Mutating the locator to search for an attribute name that appears nowhere left the sweep
green: a canary asserting an empty result cannot distinguish "found nothing" from "stopped
looking". The test now checks the locator against a reader — `value = query.semantic` — before
trusting it about their absence. Third instance in this branch of the same mechanism: a check
