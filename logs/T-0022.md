## Why two entries are graded `LOCKED`

Neither RFC 0013 D3 nor §11's phasing carries a live grade — 0013 is retired, and §11 is
prose rather than a row in §10's table. `flag-dont-flip` is explicit about that case:
an ungraded decision is treated as `LOCKED` and a contradiction halts rather than guessing
a grade. Both entries are halts, not departures.

## Plan — and the readiness gate

Three load-bearing entries above, none of them a detail of the others. `flag-dont-flip`'s
gate says that is a spec not ready to execute, and that executing it anyway produces a
second design expressed in code. Reported rather than built. No source file has been
touched on this branch.

## Accepted — the author's decision, 2026-09-06

The three entries above were put to the author with the trade-off, and the re-scope was
accepted. RFC 0040 now carries D9, D10 and D11 in §10, each citing the entry that forced
it, and a §11a superseding §11's phasing. Nothing in §5 or §11 was rewritten: both keep
their text and carry a pointer to what replaced them, so the disagreement that produced the
revision stays readable.

What the rows say, in one line each:

- **D9 (`LOCKED`)** — P2 is proof-backed refusal. The single-hop rollup has no route to SQL
  and no route from a spec.
- **D10 (`ASSUMED`)** — cross-grain capability, when wanted, is RFC 0041's aggregate-then-join,
  never a `PreservingJoin` over unaggregated rows.
- **D11 (`LOCKED`)** — a refusal changing exception class is a parity event, even with no
  capability behind it.

P3 and P4 are withdrawn as written rather than re-scoped: both inherit D-132's missing
execution story whole, and phasing work that cannot say what executes it is the thing this
log stopped P2 for.

## Findings — self-audit, 2026-09-06

Scope: the whole branch against `main` (60bb235), 2 commits / 15 files / +663−19 at the
time of audit — source, tests, fixtures, docs, the RFC amendment and this log. Gates re-run
after every fix.

### 1 — the parity suite could not see the only thing this phase changed

`test_only_the_licensed_conversion_moved`'s ancestor passed, and it was worthless here. The
generator asked, for each mart, only that mart's own dimensions — so **not one of its 556
requests could reach a cross-mart dimension**, which is the sole behaviour P2 alters. The
suite RFC 0040 §8 calls load-bearing was blind to the phase it was guarding, and it reported
green for the same reason a broken thermometer reads room temperature.

Fixed by extending the generator with each measure by every dimension another mart of the
same project flattens (+144 requests), and regenerating the baseline **in a worktree of the
merge base** so the conversion is a diff rather than a number. It shows 129 requests moving
`UnknownMember` → `UnreachableAtGrain`, 0 moving any other way, 0 dropped — which is exactly
what D11 asks a converting phase to produce.

Worth saying plainly: without this, the branch would have shipped with its central claim
unverified and a green suite next to it. The commit message even said "no request that
existed before this phase moved" — true, and true only because none of them could.

### 2 — the rule that licenses the conversion was itself unexercised

With the suite extended, sabotage replaced the whole `unlicensed` computation with `{}` and
the suite stayed green: the other assertions in that test carried it. The one assertion
holding the guarantee — that *no other* movement is allowed — had nothing to reject.

Extracted as `_unlicensed` and tested against moves the corpus does not contain: a refusal
becoming an acceptance, a different pair of classes, and the licensed pair run backwards.
The reverse case was found by a second sweep, which showed that comparing the pair as a set
survived — and a set comparison licenses this change being silently undone.

### 3 — a reachable branch with no test

`_not_here`'s "this project maps no entity for one of those grains" branch is reachable in
four fixtures, whose quality marts take their grain from the run rather than from an entity.
Coverage named it (`353-357`) and no test ran it. It is a detection branch: it only runs when
the diagnosis cannot be stated, which is when getting the message right matters most.

What made it easy to miss is that reaching it needs a dimension that really is on the other
mart; every plausible-sounding name lands on `UnknownMember` instead. Tested now.

### 4 — a comment describing the shape before the restructure

The `# pragma: no cover` comment said the open-proof case exists "which is the whole reason
the branch above tests `closed` rather than presence". After mypy forced the branches apart
there is no branch above — that one is first. A comment that describes an earlier draft is
worse than none: it sends a reader looking for code that is not there.

### Verification

`just quality -s` nine checks · `just test` · `just coverage` exit 0 · docs clean · patch
coverage **100% (28/28)**. Sabotage: **16 mutations, 15 caught** by distinct relevant tests,
baseline green and restore hash-verified.

The survivor is `open-proof-authorizes` — disabling the unreachable open-proof branch changes
nothing, because nothing reaches it. Reported rather than forced: the mutation that *does*
bite is `basis-provenance-opened`, which flips one basis to `INFERRED_HEURISTIC` and turns
the branch live, and it is caught. An unreachable guard cannot be killed by mutating itself;
what can be pinned is the invariant that keeps it unreachable, and that is pinned.

### What I would still distrust

- **Only one `RefusalReason` reaches the new renderer through a fixture**
  (`no_functional_path`). The rendering has no per-reason branch and all eight members are
  exercised in RFC 0037's and RFC 0039's own suites, so this is thin rather than absent —
  but nothing asserts that every reason produces a message an author can act on *here*.
- **`unverified` is a code no test can produce**, by construction. Its wording has been
  read and never seen.
- **The 40 `unflattened_hop` rows record a first value, not a preserved one.** They cannot
  regress against a merge base that does not contain the fixture, and that is a permanent
  property of any fixture added with a phase.

### Correction to D-135's proposal

D-135 proposed giving `UnreachableAtGrain` a `refutation` field. What shipped is
`refusal_reason`, a plain string — because `errors` is the bottom layer of the import
contract and `Refutation` lives in `semantic`, above it. The field follows
`UnsupportedFilter.nearest_supported`, whose docstring already argues the same case: the
*value*, not the member, so `RefusalReason(err.refusal_reason)` round-trips.

Appended rather than corrected in place. The entry was right about the shape of the answer
and wrong about its type, and the reason it was wrong — a layer boundary — is worth more in
the record than a tidy proposal would be.

### Correction to D-139's claim about reachability

D-139 says the divergent-column case is "Not reachable end to end on today's corpus, which
is why it is tested against the divergent column directly." That was true when the entry was
written and **false by the time the commit landed**: extending `unflattened_hop` with the

## D-143 — two witnesses answer "exactly one route"
