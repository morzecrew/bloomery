## D-132 — P2's capability has no route to SQL

```divergence
decision: RFC 0013 D3 — never a semantic model for a non-mart entity
grade: LOCKED
class: spec-gap
at: 2026-09-06T11:15:00Z
attempt: 1
claim: §5's accepted example is `Scan(Order) -> PreservingJoin(Customer) -> Aggregate(...)` — a join performed at query time. bloomery has exactly one SQL generator, MetricFlow, and its manifest emitter states as a pinned decision that there is "never a semantic model for a non-mart entity — that would reintroduce the query-time joins the mart design exists to prevent (RFC 0013 D3)". So there is no relation for a `PreservingJoin` to reach, and no second generator to reach it with. §6 says target adapters receive a plan; it does not say what a target does when the plan names an operator that target was built to refuse
evidence: src/bloomery/emit/metricflow/__init__.py:9-12
action: halted
proposal: §6 or §11 gains the missing half — what executes a P2 plan. Three shapes, each touching a decision made elsewhere: emit entities for reachable-but-undeclared relationships (widens the manifest against RFC 0013 D3's stated reason); give bloomery its own SQL for this class (a second generator, departing D6); or make P2 prove-and-refuse-better with no capability change (departs §11's phasing). None is a detail of the other two
```

## D-133 — the class P2 converts is empty in this codebase

```divergence
decision: RFC 0040 §11 — P2, single-hop rollup, one proven many_to_one/one_to_one dimension path
grade: LOCKED
class: discovery
at: 2026-09-06T11:20:00Z
attempt: 1
claim: for a single hop to convert a refusal, a project must declare a relationship from a mart's grain entity and *not* flatten it onto that mart. Where the relationship is declared, `flatten: {via: ...}` already brings the dimension onto the mart at build time and the request is accepted today; where it is not declared, no proof is possible and the correct answer stays a refusal. Across every buildable fixture there are zero marts with an unflattened single hop from their own grain, so P2 as specified would ship a proof rule with no input — and its acceptance tests would need a fixture written to be the only thing that exercises it
evidence: `<probe over every buildable fixture, counting relationships from a mart's grain entity absent from that mart's joins>` -> `UNFLATTENED SINGLE HOPS FROM A MART GRAIN: 0`
action: halted
proposal: §11's P2 says what to prove and not when the question arises. Either name the shape that reaches it — an author who declares a relationship and deliberately does not flatten it, which is a spec pattern nothing today encourages — or re-scope P2 to the case the corpus does hold: a dimension carried by a *different mart* whose grain the measure's mart can reach. That case is real (`multi_mart_refusal` refuses `line_discount by order_date` with `UnknownMember` today) but needs a relationship the fixture does not declare, and needs D-132 answered before it can execute
```

## D-134 — a refusal changing class is a parity event, and §8 pins outcome

```divergence
decision: RFC 0040 D8 — whether refusals for already-refused requests may change wording
grade: OPEN
class: spec-gap
at: 2026-09-06T11:25:00Z
attempt: 1
claim: D8 was settled during P1 as "the parity suite pins the outcome and the exception class, never the wording" (logs/T-0021.md, D-119). P2's candidate cases are refused today as `UnknownMember` — an unknown *dimension* on the covering mart — not as `UnreachableAtGrain`. Any P2 shape that converts them therefore changes an exception class, which the parity suite is built to fail on, and §11's "except where a new documented proof rule deliberately converts one class" is the licence to edit the baseline. What is unsettled is narrower: whether a request that stays refused should move from `UnknownMember` to a proof-backed refutation, which is a class change with no capability behind it
evidence: `planner.plan(multi_mart_refusal, metrics=('line_discount',), dimensions=('order_date',))` -> `UnknownMember: unknown dimension 'order_date' on mart 'order_items'; did you mean 'order_id'?`
action: decided
proposal: D8 gains the sentence P1 could not need: a phase converting a refusal edits `parity_baseline.tsv` and names the rule in the commit, and a phase changing only a refusal's *class* without adding capability is a parity event too, not a wording change exempt from the suite
```

## Why two entries are graded `LOCKED`

Neither RFC 0013 D3 nor §11's phasing carries a live grade — 0013 is retired, and §11 is
prose rather than a row in §10's table. `flag-dont-flip` is explicit about that case:
an ungraded decision is treated as `LOCKED` and a contradiction halts rather than guessing
a grade. Both entries are halts, not departures.

## Plan — and the readiness gate

Three load-bearing entries above, none of them a detail of the others. `flag-dont-flip`'s
gate says that is a spec not ready to execute, and that executing it anyway produces a
second design expressed in code. Reported rather than built. No source file has been
touched on this branch.

## Accepted — the author's decision, 2026-09-06

The three entries above were put to the author with the trade-off, and the re-scope was
accepted. RFC 0040 now carries D9, D10 and D11 in §10, each citing the entry that forced
it, and a §11a superseding §11's phasing. Nothing in §5 or §11 was rewritten: both keep
their text and carry a pointer to what replaced them, so the disagreement that produced the
revision stays readable.

What the rows say, in one line each:

- **D9 (`LOCKED`)** — P2 is proof-backed refusal. The single-hop rollup has no route to SQL
  and no route from a spec.
- **D10 (`ASSUMED`)** — cross-grain capability, when wanted, is RFC 0041's aggregate-then-join,
  never a `PreservingJoin` over unaggregated rows.
- **D11 (`LOCKED`)** — a refusal changing exception class is a parity event, even with no
  capability behind it.

P3 and P4 are withdrawn as written rather than re-scoped: both inherit D-132's missing
execution story whole, and phasing work that cannot say what executes it is the thing this
log stopped P2 for.
