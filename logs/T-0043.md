# T-0043 · Spec timeline

Executing RFC 0069 P1 against branch `feat/spec-timeline`.

## Plan

§12's P1: the value type, `timeline()`, identity matching and absence handling.
`facets` is present and empty; the delta is RFC 0064's and is not built here, and
the CLI command is P3's.

One `pipeline()` pass per history entry yields both that version's graph — which
decides presence, in the same vocabulary `bloomery lineage` answers in — and its
IR, which decides change. Identity is carried forward as `(name, id | None)` and
re-resolved per adjacent pair, per D12.

Out: any facet vocabulary (D3), any reading of a label (D1), any fetching (D2),
the CLI (D6, D8).

## Self-audit — 2026-09-11

Scope: the whole branch against `main` — 3 commits plus the audit's own fixes,
16 files, +1723/−15, merge base `ded2179`. Every pass ran. **Eleven findings, all
fixed**, and the three that matter all came from the sweeps rather than from
re-reading.

1. **A step output read as a node that never changed.** `_step_edges` mints
   `entity_field_node(<produced relation>, <output name>)` per `outputs:`
   entry, so `customer.customer` is a node of kind `ENTITY_FIELD` naming a
   *relation*, and `customer` has no column called `customer`. The per-kind
   lookup found nothing — and nothing is exactly what a node whose definition
   never moved looks like, so every step output in every project would have
   read "present in every version, changed in none". Recorded as an entry above
   with its measurement. Fixed: an entity field with no matching column is the
   produced `EntityIR`, and `test_a_step_output_is_the_relation_it_produces`
   pins it. **This is the finding the whole audit was worth**, and it is worth
   saying how it was found: not by reading the table, which I had read twice,
   but by writing the sweep that checks the table against every node of every
   fixture. The claim it was written to confirm was the thing that was wrong.

2. **A docstring claim no test could have failed for.** `_entity_field` says
   comparing only the lowering "would miss a retyped column" — and replacing
   the `ColumnIR` with `None` passed the entire suite, because in
   `evolution_v1`..`v2` the retype moves the cast *inside* the lowered
   expression too. The corpus co-varies the two halves and cannot separate
   them. Fixed with `required:`, which moves the schema alone, and the test
   asserts the lowering is identical across the pair so the premise is its own
   rather than the reader's.

3. **Identity across a gap was untested.** Clearing the carried identity when a
   node is absent gives the *same* answer as the correct code for the gap test
   — both suppress the change — and the wrong one when the node is renamed
   while it is away. Two mutants (clearing the whole identity, clearing only
   the id) both survived. Fixed by a four-entry history asked by the name the
   first version used, which only the id picked up in the second and carried
   across the third can reach.

4. **A redundant conjunct nothing could distinguish.** `_locate` asked both
   `held.node_id in by_id` and `held.node_id in present`, and dropping the
   second killed no test. That is not a coverage gap: `node_keys` and
   `build_graph` read one source, and `effective_metrics` yields one metric per
   authored metric, so an id the adoption map names is an id the graph carried.
   Removed rather than left with a comment defending it.

5. **The unreachability of `_definition`'s remaining branches was argued, not
   measured.** They were marked `# pragma: no cover` on my reasoning. The sweep
   written to measure that reasoning is what produced finding 1, which is the
   point: the argument was sound for four kinds and false for the fifth.

6. **One of §6's nine test items was silently deferred.** "The facets are RFC
   0064's, asserted against that vocabulary" has no vocabulary to assert
   against. Logged as an entry above rather than left as a list that reads
   fully satisfied.

7. **Two pages teaching one label convention in two spellings.** The reproduce
   how-to recommended "ISO-8601" — the too-wide claim D10 supersedes row 9 for
   — and the two pages now link to each other. Narrowed, and logged.

8. **`CHANGELOG.md`'s link was a repo path** where every sibling entry uses the
   published URL. Fixed.

9. **`test_every_docs_page_is_in_the_nav`'s docstring pinned "34 pages and 34
   entries"**, a count this branch moved. Rewritten to state the property and
   to say why the counts are deliberately not asserted.

10. **`pytest.raises(Exception)`** where `UnknownStep` is the class the
    docstring beside it names. Tightened.

**A second round over the audit's own fixes found one more, and it is the
kind only a sweep finds.** After crossing a rename by id, `_locate` returns the
name it *found*, and keeping the carried one instead survived every test. Two
entries cannot show it: a stale name finds no metric, which reads as a
definition that moved, which is what a rename reports anyway. It takes a third
entry and a project where the old name has been **reused** — then the stale
name stops finding nothing and starts finding somebody else's definition.
`test_an_id_match_picks_up_the_new_name_it_found` is that history. Nothing in
the source changed; the gap was in what the suite could distinguish.

**Verification.** `just quality -s` 9 of 9; `pyright src` 0 errors;
`just build-docs` clean; 4568 passed / 5 skipped; global coverage 99.13% with
`resolve/timeline.py` at 100%. Fifteen hand-written mutants over the walk, the
identity rule and the per-kind table, then four more over the audit's own
fixes: **18 killed, 2 survivors**, and both are diagnosed rather than assumed.
One of the four — `rest.strip()` on a string that never carries whitespace — is
an equivalent mutant I wrote badly rather than a gap, and is recorded as such
because a survivor with no explanation is the finding.

**The survivor is an equivalent mutant against the stated contract.** Replacing
the single `for` over `history` with `list(history)` and a loop over the list
survives, and should: D2 and §5.1 promise the history is "consumed once, in
order, and never re-iterated", and all three hold under it. What it changes is
buffering — sixty entries fetched before the first is compiled — which is a peak
memory property nothing in the document promises. Distinguishing it would need
a test that observes interleaving between the caller's generator and the
compile, and pinning an unpromised property is how a suite acquires tests that
refuse a legitimate change later.

**Residue.** Three things I would still distrust:

- **An unreachable metric compares coarsely.** The IR keeps an
  `UnreachableMetric` — name, missing leaves, chain — and not the definition,
  so an edit leaving a metric unreachable for the same reason is invisible.
  Pinned by `test_an_unreachable_metric_is_compared_coarsely_and_that_is_stated`
  so the limit is a fact rather than a footnote, with the reachable case beside
  it.
- **A step output named after a real column is ambiguous**, and the ambiguity
  is the graph's: `outputs: {canonical_id: ...customer}` mints the id a field
  of `customer` would, and nothing downstream can separate them. Not created
  here and not fixable here.
- **An entry that does not compile takes the timeline down with it.** Decided,
  logged and documented, not tested against a real historical spec set — no
  such corpus exists in this repository.
