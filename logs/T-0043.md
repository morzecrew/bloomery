# T-0043 · Spec timeline

Executing RFC 0069 P1 against branch `feat/spec-timeline`.

## Plan

§12's P1: the value type, `timeline()`, identity matching and absence handling.
`facets` is present and empty; the delta is RFC 0064's and is not built here, and
the CLI command is P3's.

One `pipeline()` pass per history entry yields both that version's graph — which
decides presence, in the same vocabulary `bloomery lineage` answers in — and its
IR, which decides change. Identity is carried forward as `(name, id | None)` and
re-resolved per adjacent pair, per D12.

Out: any facet vocabulary (D3), any reading of a label (D1), any fetching (D2),
the CLI (D6, D8).

It is the same argument RFC 0017 §5.3 makes and RFC 0068 D1 restates: a registry is a caller-assembled compile input, so the party assembling the history is already the party holding it. Defaulted, so the common case — a project with no steps — writes nothing. Not `LOCKED`: the alternative worth naming is that an entry carry a prebuilt `ProjectIR` instead, which §10 already has open as a cache question and which would make this field redundant rather than wrong.

```divergence
decision: unlisted
grade: UNLISTED
class: spec-gap
at: 2026-09-11T14:16:12Z
attempt: 1
claim: §12 says the comparison is "IR equality per node", and the IR has no record for two of the seven node kinds. `ProjectIR` carries entities, metrics, unreachable, relationships, marts, rollups, exposures, date_dimension, fx_rates, reconcile, coverage and steps — there is no canonical-field record anywhere in it (a canonical field survives only as `ColumnIR.canonical`, a string reference) and no source-column record. An entity field's definition is split further: the schema half is a `ColumnIR` and the lowered expression half is one `SourceColumnIR` per source, joined by name. So "the node's IR" is undefined for `canonical.*` and `source.*` and ambiguous for `<entity>.<field>`
evidence: src/bloomery/ir/nodes.py:1439-1456
action: decided
proposal: ASSUMED — the compared value is per kind: the `MetricIR` for `metric.*`, the `MartIR` or `RollupIR` for `mart.*`, the `ExposureIR` for `exposure.*`, the `StepIR` for `step.*`, the `ColumnIR` with each source's `SourceColumnIR` for an entity field, the catalog's `CanonicalField` for `canonical.*` — the only record of one that exists anywhere — and **nothing** for `source.*`, which has no definition beyond its existence: a source column is a bronze path, and presence is the whole of what can change about it. Forced rather than chosen for the last two. §12's sentence stays true of the four kinds it is true of; the table is what it means for the rest. `test_every_node_kind_has_a_definition_rule` walks `NodeKind` so a kind added later cannot fall through this silently.
```
