# T-0049 · Unparseable SQL is a refusal, not a crash

No RFC governs this branch. RFC 0002 — which decided that every compile failure leaves the
boundary as a `BloomeryError` — is retired, and the defect being fixed is a violation of
that retired decision rather than a departure from a live one. `flag-dont-flip`'s fallback
therefore applies to the whole task: every decision here is **unlisted**, decided by the
executor, and recorded with its evidence.

## The defect

Unparseable SQL text reaches `sqlglot.parse_one` unguarded and crosses the compile
boundary as a raw sqlglot exception. `resolve/steps.py:729-750` already fixed this for one
door — a step body — and its comment names the exact trap the fix has to avoid.

## Self-audit — 2026-09-12

Scope: `main...HEAD`, 10 files, +447−39 at the time of the sweep. Four findings, all
fixed on the branch; the entries below are the decisions two of them forced.

**1. A too-deep expression still crashed.** SQLGlot's parser recurses on nesting depth,
so ~400 nested parentheses raise `RecursionError` — not a SQLGlot class — and walk out of
a handler catching only `SqlglotError`. Pre-existing and identical on `main`, but these
two doors are now the first and only place these fields are parsed, so a boundary total
except for one input class is not total. Both doors catch it. Fixed.

**2. A wrong explanation in two published documents.** The changelog and the stability
reference both described an unreached metric as one "no mart makes reachable".
Reachability is a canonical field no mapping supplies (`ir/nodes.py:1007` — "the fix is
always a mapping"); marts have nothing to do with it. Classed `drift`: the code said what
reachability means and the prose was written from memory anyway. Fixed.

**3. The validator was free to rewrite what it validated, and nothing said otherwise.**
Sabotaged to `return parse_one(expr).sql()` — normalising every authored expression
through SQLGlot — the whole default profile stayed green: **4843 passed**. The authored
string is what reaches the IR and the fingerprint (RFC 0003), so that mutant moves every
project's fingerprint silently. It survives because the fixture corpus is already written
in SQLGlot's own spelling, which makes the rewrite a no-op on every input the suite owns.
One test now pins byte-identity on a spelling SQLGlot would change. Fixed.

**4. A survivor that was not a gap.** `return expr.strip()` also survived, and the reason
is a second guard rather than a blind test: `SpecModel` sets `str_strip_whitespace`, so
every spec string is stripped before the validator sees it. A true equivalent mutant —
recorded because "why did it survive" is the finding, and the first draft of the test
above chased it and failed against correct code.

**Sabotage:** 12 mutants over the change surface, 12 killed, plus 2 behaviour-preserving
controls that survived — the sweep can report SURVIVED, so the kills mean something.
Then 3 more mutants on the return path: 2 killed by the new test, 1 equivalent (above).

**Coverage:** patch 14/14 lines (100%); global 99.17%, guardrails 100%, steps 92.5% — all
three floors met.

**Checked and clean:** the exported JSON Schema is unchanged (an `AfterValidator` adds no
keyword), which is the same thing already true of `MemberName`'s reserved-name check —
consistent with its surroundings rather than a new divergence. Parse-at-load costs
nothing measurable (150.25s → 150.60s across the default profile).

**Residue — what I would still distrust.** Every other `parse_one` in the tree keeps the
recursion exposure; only these two doors were closed, and only for the four fields they
own. `a; b` still parses as a `Block` everywhere except an expression rule.
