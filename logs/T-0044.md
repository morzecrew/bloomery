# T-0044 · Stable node identity: plan() and display

Executing RFC 0062 P2 and P3 against branch `feat/node-identity-plan-and-display`.

## Plan

P1 kept the authored `id:` out of the IR, deliberately, so that an unadopted
project compiles byte for byte (D3). P2 and P3 both need the id *downstream* of
the IR, and that is the whole shape of this phase: the id reaches `plan()` as an
argument the caller derives, and reaches `lineage`'s rendering from the
`Project` the command already holds.

One new public function, `node_labels(project, catalog)` — node id to the name a
reader knows it by, for every node that adopted an id — built with the same node
constructors that mint the ids, so the inversion cannot drift from the
construction. `plan()` gains two keyword-only, defaulted parameters taking that
map for each side. `render_lineage` takes it too.

Out: any change to the IR (D3), any similarity heuristic (D1), any re-spelling
of an existing node id (D7), and the `explain` half of §5.4 — see the entry
below.

```divergence
decision: unlisted
grade: UNLISTED
class: spec-gap
at: 2026-09-11T16:38:13Z
attempt: 1
claim: §5.3 says `plan()` gains a second RENAME producer — "a node whose id is present on both sides with a differing name" — and `plan()` cannot see an id. Its signature is `plan(old: ProjectIR | None, new: ProjectIR)`, and neither `MetricIR` nor `StepIR` carries an `id` field, because P1 substitutes the id while building node ids and keeps only names in the IR. The obvious repair is what D3 forbids: the canonical encoder writes each dataclass's field *count* and every field *name*, so a defaulted `id=None` moves the bytes of every project with a metric, adopted or not
evidence: `uv run python -c "..._canon_bytes on a two-field vs three-field dataclass..."` -> `b'CS6:Before2:S4:name...'` vs `b'CS5:After3:S4:name...S2:idN'` — the count and the field name are in the stream whatever the value is
action: decided
proposal: ASSUMED — `plan(old, new, *, old_labels=..., new_labels=...)`, keyword-only and defaulted to an empty mapping, each the node-id-to-name map for its side. Every existing call site keeps working and keeps today's report; a caller that wants rename detection passes the maps, which one public call produces. No IR field, so D3 holds byte for byte. The alternative worth naming is handing `plan` the two `Project`s, which reads more naturally and re-admits the spec layer into a diff whose whole design is that it consumes IR.
```
