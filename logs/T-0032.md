## Self-audit — 2026-09-09T14:22:27Z

Whole branch, 2 commits / ~710 lines before the audit's own fixes: 5 source files, 9 test
files, 6 documents, 1 task file. Scope from `audit_scope.py scope --base main`.

**Five findings, all fixed.** The first is a real defect and the sweep did not find it —
it found that the ground the defect was on had never been walked.

### 1. Two reference sites missed, and the graph split (fixed)

Recorded as its own `drift` entry above. The rule — every reference resolves through the
key map — was written in this log *before* the code, and two of the four canonical
reference sites did not follow it: a mapped entity field's `canonical:` link and a step
wiring's `canonical` output link. An adopted canonical id produced both
`canonical.<id>` and `canonical.<name>` in one graph, which is the exact failure the
entry describes.

What found it was not the sabotage sweep. The sweep said
`canonical-refs-not-resolved` **survived**, which meant only that no test adopted a
canonical id; writing that test failed on the first assertion. The mutation pointed at an
unexercised branch and the branch turned out to be broken.

The step-link twin then survived a second sweep, because the step fixture used above
declares no `canonical:` block. It needed `identity_resolution`, which does.

### 2. An empty id minted a bare prefix (fixed)

`id: ""` satisfied every rule in the document — a string, compared, never parsed — and
produced the node id `metric.`, which is the prefix and nothing else. The metric then
answered to a name no reader would guess and vanished from any lookup of its own. Refused
at parse with `min_length=1`, which is a boundary constraint rather than the parsing D2
forbids: nothing reads into the value and any non-empty string still passes.

### 3. The refusal pointed at a document, not into it (fixed)

`source_path` was the bare document kind — `metrics` — where every other refusal in this
stage spells `metrics: metrics.<name>`. An author got a file and the job of finding which
entry was at fault. It anchors on the first claimant now, and the message names them all.

### 4. Two lists of node kinds, one of them able to go quiet (fixed)

`node_keys` enumerates the kinds and so does the refusal. Reverting the loop to drive off
its own list changed no test, because the two agree today; what it buys is the day they do
not, when a kind added to the map and forgotten in the refusal would be a kind whose
collisions nobody checks. The loop is driven off the key map, so a missing kind raises, and
a test patches a fourth kind in to prove it.

### 5. The spec-schema goldens moved (regenerated, with the diff read first)

Recorded as a second D3 close-out above. Three goldens gained one optional property each —
the vocabulary genuinely gained a key, and an editor validating against the old schema
would reject a legal document. Checked before regenerating rather than after: regenerating
a golden to make a test pass is how a real regression gets laundered, and the whole diff is
`id` under `CanonicalField`, `Metric` and `StepWiring` with no reordering.

### Noted, not a defect

**§6's `plan()` tests are P2's.** "A rename is a rename" and "a delete is still a delete"
both need `ChangeClass.RENAME`'s second producer, which §12 puts in P2. P1's share of §6
is the traversal, the byte-exact opt-out, opacity and the namespace guard, and all four are
here.

**Where the key map lives.** `spec/project.py`, not `resolve/graph.py`, because the
guardrail is below `resolve` in the layer contract and cannot import it — the same reason
`NODE_ID_PREFIXES` is in `ir` rather than beside the builders. Two copies would be two
answers to "what is this node called".
