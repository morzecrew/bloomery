# T-0047 · Declared source freshness

Executing RFC 0057 against branch `feat/declared-source-freshness`. Both phases of §12:
the spec key with its three refusals, then the dbt `sources.yml` branch.

**Drift count: 0.**

Where building this disagreed with the design for it, written at the moment it happened.
Nothing here is revised afterwards to agree with what was later settled, and nothing here
has been folded back into the RFC's own text. The rows proposed below are put forward for
the author to accept or refuse; execution does not write them into a decision table
itself.

| Class | Test | Meaning |
|---|---|---|
| `discovery` | Could not have been known before code existed | Healthy — the spec was right to be silent |
| `spec-gap` | Could have been known; the spec was silent or at the wrong altitude | The design process missed something |
| `drift` | The spec covered it and it was built otherwise anyway | **A defect** |
| `irreducible` | No amount of design settles it | Stop and spike |

## Plan

Two commits, §12's. The first is the risky half and lands alone: the `freshness:` key,
`FreshnessIR` on `SourceIR`, the parse refusal for an inverted pair, the two guardrail
refusals (a threshold where no `_ingested_at` is required, and two mappings disagreeing
about one relation), and the two *legal* cases pinned — equal thresholds collapsing and
the mixed declare/omit case — because "this is allowed" is the half a refusal-shaped
phase forgets. The second adds the emitter branch, its golden, and the
`dbt source freshness` leg.

Out of scope, and not deferred inside this: measuring freshness, `SpecEvidence` intake,
schedules, mart SLAs, and dbt's `filter:` escape hatch (§10, undecided — a threshold with
no `filter:` is what this builds).

## Self-audit — 2026-09-12

Scope: the whole branch against `main` — 2 commits, 215 files, +1562-457, merge base
`02e9117`. 196 of those files are regenerated goldens: the IR version bump moves every
fingerprint header, which is the bump working as intended. Every pass ran.

**Six findings, all fixed.** Four came from the sabotage sweep or from asking what a test
would still pass on; two from re-reading prose against the code beside it.

1. **`loaded_at_field: _ingested_at` did not run** — the branch's one real defect, and the
   reason the RFC asked for this leg. Found by executing `dbt source freshness` against a
   seeded warehouse: *Expected a timestamp value when querying field 'last_modified' ...
   received value of type 'str'*. `_ingested_at` is a bronze landing column and may be
   text; the emitted threshold is now the cast expression, rendered in the target's
   dialect. Entry above; pinned in `tests/unit/test_emit/test_dbt.py` as well as e2e, so
   the cheap tier keeps it.

2. **`_DBT_PERIOD` had no totality test** while `duration_hours` did. A unit added to
   `RETENTION_PATTERN` would parse, order correctly, reach the emitter and raise
   `KeyError` there — a crash at emit for a value the parser accepted. Both tables are now
   swept against the pattern's own character class.

3. **The dbt how-to claimed emitted bytes with nothing behind it.** A retyped
   `sources.yml` entry is exactly the docs failure this repo already guards elsewhere: a
   reader trusts it, and nothing fails when it rots. The block is now the literal output
   of a real compile of `multi_source_quality`, pinned by
   `test_the_emitted_freshness_block_is_what_dbt_gets` with its own can-fail control.

4. **D6 was an absence, not a decision.** "SQLMesh and Cube emit nothing, and it is not a
   refusal" was carried only by goldens, and an artifact set that never mentions freshness
   looks the same whether the emitter considered it or never saw it. Both targets now have
   an explicit test — each asserting first that its fixture actually declares a threshold,
   so the corpus reaches the feature instead of abstaining.

5. **A dead guard in the agreement check.** `if m.freshness` appeared twice inside a loop
   whose own filter made it unfalsifiable, which reads to the next person as a case that
   can occur. The threshold is now carried in the pair the filter established it from.

6. **A comment said "last writer" where the code keeps the first.** `tables.get(relation)
   or origin.freshness` deliberately lets a declaring mapping outlive a silent sibling
   (D2c) — the opposite of what the comment described, and the mutation that removes the
   `or` is killed by a test the comment would have argued against.

**Sabotage: 23 mutants, 23 killed, 0 survivors** — over the parse refusal, the duration
ordering, both guardrails, the emitter's merge, the cast, the week conversion, the plan
classification and the IR version. The apparatus was checked rather than trusted: two
behaviour-preserving controls (a local rename, `24 * 7` spelled `168`) both **survived**,
and the baseline was green before and after, so "everything died" is a property of the
tests rather than of a broken restore.

**Patch coverage: 100% (67/67 added lines)**, measured with the full profile including
e2e; global 99.16%, guardrails 100%.

**Deliberately not applied.** §6 says "every existing golden unchanged". Every golden
moved, because a nested IR field addition that does not bump `bloomery_ir_version` leaves
a project with no thresholds encoding identically before and after the field existed —
the version 7 precedent, recorded in `ProjectIR`'s docstring. The RFC's expectation was
about the *content* of `sources.yml`, which is unchanged for every relation that declares
nothing, and that is what `test_a_source_with_no_threshold_carries_neither_key` pins.

**Residue.** Two things this branch does not prove. `dbt source freshness` is executed
only against DuckDB, so the emitted `CAST(... AS TIMESTAMP)` is proven runnable on one
adapter and merely rendered on the others. And the emitter trusts the IR: handed a
hand-built `ProjectIR` carrying two different thresholds for one relation — which the
guardrail refuses and no compile can produce — `_sources_artifact` keeps the first rather
than refusing. That is the same trust every other branch of the emitter places in the
guardrail stage, and it is stated here rather than left to be discovered.

### Round 2 — 2026-09-12

Re-audited the six fixes and the four guards round 1 added, per pass 8. **No new
findings.**

Seven mutants over what round 1 introduced — a grammar unit with no dbt period, a bogus
period value, a leaked threshold in each of the two targets D6 says emit nothing, two
drifts in the how-to's pinned block, and the agreement message losing its second side —
**all seven killed**.

One earlier attempt at the SQLMesh mutant survived and was not a finding: it bound a
string to a dead local, so it changed no artifact. That is an equivalent mutant by
construction rather than a blind test, and the corrected version — the same string in the
model envelope, where it reaches an artifact — is killed by the new D6 test. Recorded
because "a mutant survived" and "the mutant was wrong" look identical in a log that only
reports counts.

Two properties of the fixes worth stating, since neither is obvious from the diff. The
emitted `loaded_at_field` is now dialect-rendered, so `models/sources.yml` is no longer
dialect-independent in principle; all three shipped dialects spell it
`CAST(_ingested_at AS TIMESTAMP)`, so nothing diverges today, and no test claimed that
identity. And the agreement check's message order is deterministic: `project.mappings` is
ordered by document name and the sort on `source` is stable, so two mappings sharing a
relation are always named the same way round.
