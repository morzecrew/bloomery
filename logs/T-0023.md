## D-145 — a ratio has one spelling, and it is not the one six specs use

```divergence
decision: RFC 0038 §12 — mint `Ratio`
grade: UNLISTED
class: spec-gap
at: 2026-09-06T18:05:00Z
attempt: 1
claim: §12 says which classes land first and D1 says the enum is closed, and neither says how a class becomes *authorable*. Every ratio in the tree is written `additivity: non_additive` with a `ratio:` block, so minting the member has to decide what happens to that pairing: derive `RATIO` from the block and leave `additivity:` partly ignored, accept both words, or accept one and refuse the other. The three differ in what the IR says about a spec the author did not change
evidence: tests/fixtures/ecom_basic/metrics.yaml:10-13
action: decided
proposal: `ASSUMED` — a metric declaring `ratio:` declares `additivity: ratio`, and any other word with a `ratio:` block is refused with the fix line. §7 and D4 already licence this direction — a project accepted today may be newly refused, "a breaking change requiring a migration note, not a silent tightening" — and the two alternatives both leave the resolved IR disagreeing with the document that produced it, which is D5's second-spelling risk installed on purpose
```

## D-146 — twenty-one sites read a member and mean a property

```divergence
decision: RFC 0038 D1 — the aggregation vocabulary is a closed typed set
grade: LOCKED
kind: resolved
at: 2026-09-06T18:10:00Z
attempt: 1
claim: `NON_ADDITIVE` is tested at twenty-one sites across the emitters, the planner and the guardrails, and at none of them is additivity the question. `metrics.py:322-328` states what the question is — "exactly the class that never emits a measure — ratio, derived, and the expression-over-components form alike" — and `nodes.py:288-291` states the same from the enum's side and names it as the debt a minting commit owes. Splitting `RATIO` out of that member silently narrows every one of those tests, and no test in the tree fails when it happens
evidence: src/bloomery/guardrails/metrics.py:322-328
action: decided
proposal: the property gets a name in `bloomery.ir` and the sites test it, so that minting the two remaining members is an enum edit rather than a second sweep of twenty-one judgement calls. This follows D1 rather than departing it: the decision is that the vocabulary is typed and closed, and a site branching on one member while meaning a class of them is what makes a closed set behave like an open one
```

## D-147 — bloomery's own generated metric was the first spec refused

```divergence
decision: RFC 0038 §12 — mint `Ratio`
grade: UNLISTED
class: discovery
at: 2026-09-06T18:40:00Z
attempt: 2
claim: the plan counted six authored ratios and called `quality/mart.py`'s two construction sites unaffected. There is a seventh, and it is not authored: `quality_quarantine_rate` is built in Python with `additivity=Additivity.NON_ADDITIVE` and a `Ratio`, so the shape guard refused a project bloomery generated itself. Three execution tests and both `semi_additive_inventory` semantic goldens failed on it before any authored spec did
evidence: `uv run pytest tests/unit/test_guardrails/test_stage.py -q` -> "metric 'quality_quarantine_rate' declares ratio: but additivity 'non_additive'. ... Fix: additivity: ratio"
action: decided
proposal: the generated metric declares `RATIO` like any other. It is the clearest instance of D2's reason rather than an exception to it — a quarantine rate averaged across entities is not the rate — and a guard the compiler's own output cannot satisfy is a guard that would have been widened instead
```
