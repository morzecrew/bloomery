# T-0023 · RFC 0038 P2 — mint `Additivity.RATIO`

Executed on branch `feat/ratio-measures`. §12's stated order — "`Additive` and `Ratio`
first" — against an enum D1 already closed at six and a `RESOLVABLE` tuple that pins the
three a project can produce. What is minted here is the fourth.

**Drift count: 0.**

Where building this disagreed with the design for it, written at the moment it happened.
Nothing here is revised afterwards to agree with what was later settled, and nothing here
has been folded back into the RFC's text. Rows proposed below are put forward for the
author to accept or refuse; execution does not write them into a decision table itself.

## D-145 — a ratio has one spelling, and it is not the one six specs use

```divergence
decision: RFC 0038 §12 — mint `Ratio`
grade: UNLISTED
class: spec-gap
at: 2026-09-06T18:05:00Z
attempt: 1
claim: §12 says which classes land first and D1 says the enum is closed, and neither says how a class becomes *authorable*. Every ratio in the tree is written `additivity: non_additive` with a `ratio:` block, so minting the member has to decide what happens to that pairing: derive `RATIO` from the block and leave `additivity:` partly ignored, accept both words, or accept one and refuse the other. The three differ in what the IR says about a spec the author did not change
evidence: tests/fixtures/ecom_basic/metrics.yaml:10-13
action: decided
proposal: `ASSUMED` — a metric declaring `ratio:` declares `additivity: ratio`, and any other word with a `ratio:` block is refused with the fix line. §7 and D4 already licence this direction — a project accepted today may be newly refused, "a breaking change requiring a migration note, not a silent tightening" — and the two alternatives both leave the resolved IR disagreeing with the document that produced it, which is D5's second-spelling risk installed on purpose
```

## D-146 — twenty-one sites read a member and mean a property

```divergence

Splitting `RATIO` out of that member silently narrows every one of those tests, and no test in the tree fails when it happens

```

## Self-audit — 2026-09-06

**Scope.** The whole branch against the merge base `9ed1d68`: 3 commits, 139 files,
+591/-290 — 10 source files, 121 test files (117 of them regenerated goldens), 8 docs.
RFC 0038 re-read first, §4, §7, §12 and the decision table, before the diff.

**What ran.** `just quality -s` 9/9 · `just test` 3928 passed, 6 skipped ·
`just coverage` exit 0 (guardrails 100%, steps 92.5% against a 92 floor) ·
`just build-docs` clean · a 21-mutation sabotage sweep over the branch's own changes,
19 caught on the first pass and 21 after the two tests the survivors named.

**Findings, worst first.**

1. **A number asserted from a grep, repeated four times before it was measured** — fixed.
   "Twenty-one sites tested `NON_ADDITIVE`" was the line count of a grep for `Additivity.`
   anywhere outside `ir/nodes.py`, `ADDITIVE` and `SEMI_ADDITIVE` included. Measured, it is
   fifteen reads of that member, twelve of which meant something else. It had reached the
   enum docstring, the canary's docstring, RFC 0038's D8 and a commit message. Everything
   editable now carries the measured figure and says what it counts; commit `b427944`'s
   message keeps the wrong one, and D-149 is where a reader meets the correction. The
   argument never depended on the number, which is why nothing challenged it.

2. **Two sabotage survivors, both masked rather than untested** — fixed. Neither was a
   blind check. `_has_no_measure` narrowed back to `NON_ADDITIVE` is invisible because its
   second clause answers the same case, so the mutation only shows on a ratio written
   *with* an `agg:`; MetricFlow's `measures` set narrowed back is invisible until a ratio
   names another ratio as an operand, which no fixture does — and which is the shape Cube
   already had a test for and MetricFlow did not. A test each, written from the masking.
   D-150.

3. **A shared message kept the caller-specific tail it was written with** — fixed.
   `_check_not_stored` is reached by both `COMPUTED` members after the split, and its
   closing clause still said "the ratio is a calculated measure at query time" — prose
   about ratios, delivered to a metric backed by an additive decomposition. Now "this
   metric is recomputed at query time".

4. **The dispatch was pinned by which members are reachable, never by each reachable one
   being handled** — fixed. `check_additivity` raises on a member with no arm, and the
   `RESOLVABLE` canary says which members exist; nothing said every one of them takes an
   arm. `test_every_resolvable_member_reaches_an_arm_of_its_own` does, verified red by
   deleting the `RATIO` arm.

**Checked and clear.**

- **D6 (`OPEN`) is not yet due.** §12 asks it to be decided "before the migration is
  written", and the migration it means is §7's origin-grain one. This branch's migration is
  the ratio word, which does not touch origin grain, so D6 is unanswered on purpose rather
  than by oversight.
- **D1, D2, D4, D5 conformance.** D1's set is unchanged in membership; D2 is strengthened
  from a convention into a refusal; D4's watched direction — newly refusing an accepted
  project — is explicit with the migration note §7 requires; D5's second-spelling risk is
  what D7 removes. D1 and D2 both have close-outs (D-146, D-150).
- **Determinism.** `COMPUTED` is a tuple, not a set, and reaches no output ordering.
- **The golden diff is what it claims.** Every non-fingerprint line is one of two Cube
  `meta.additivity` words or two schema enum entries; no SQL, no MetricFlow shape, no
  calculated-measure expression moved.

**Residue — what I would still distrust.**

- **`COMPUTED` is complete for six members on inherited authority.** That `SNAPSHOT` and
  `DISTINCT_COUNT` are stored measures comes from the enum docstring T-0019 wrote, not from
  anything this branch established. It is the claim D8 rests on, and the commit that mints
  either member is where it gets tested rather than repeated.
- **`pages/docs/concepts/guardrails.md` quotes a message the code does not emit.** The
  rendered `AdditivityViolation` block is a paraphrase, and was before this branch. It is
  coherent as an illustration of a ratio; it is not the artifact as emitted.
- **`ratio:` alongside `agg:`/`expr:` is unrefused.** Nothing rejects the pairing; the
  metric is correctly treated as computed, and the aggregation is simply ignored. The new
  cumulative test pins that the *consequence* is right. Refusing the pairing outright is a
  shape rule this phase did not add.
