### Findings

**1 · A currency column whose own chain converts was spliced into the rate lookup.**
*Fixed, `0d5fdf02`.* Severity: silent wrong answer.

`_anchor_expression`'s docstring argued that a re-lowered sibling can never itself
contain a conversion, and named `to_string` as the reason. It is the counterexample:
`{to_decimal: [12, 4]}`, `{convert: [EUR, USD, paid_at]}`, `to_string` declares a
`string` column, so nothing about the type stopped it being named as a currency column.
Reproduced: the inner conversion was spliced inside the rate lookup with its anchor
still the field *name*, so the emitted predicate read `'paid_at' >= fx.valid_from` —
a string literal against a date, matching nothing, in SQL that compiled. Now a guard,
for both sibling roles rather than the one that can reach it, because the argument that
protects the anchor is a fact about today's transform vocabulary.

**2 · A bridged chain emitted a call no engine defines.** *Fixed, `1f3289d9`.*
Pre-existing on `main`; severity: run-time failure on a clean compile. See the D3
close-out above.

**3 · A missing exchange rate was reported as a failed cast.** *Fixed, `e6ebd0d1`.*
Pre-existing; severity: a good row withheld with the wrong reason. See the third
entry above.

**4 · Two branches the sweep found nothing reaching.** *Fixed, `74fbc612`.* A per-row
bridge hop's ISO check, and the self-conversion skip — which is only observable with a
column named exactly like the target currency, since `MemberName` puts no case rule on
a column. Both now have a test; the second is why the skip exists at all.

### Residue — what a reader should still distrust

- **A `currency_in:` on a field that never converts is accepted and never read.** True
  of the literal spelling since P1 and of the column spelling now, so a
  `currency_in: {column: no_such_column}` beside a non-converting `from:` names nothing
  and nobody says so. Left alone rather than fixed: it is one rule about unread
  declarations, it is not per-row's, and inventing it inside this task is the amendment
  `flag-dont-flip` refuses.
- **`nullifies` is per chain, not per step.** A converting column now gets no implicit
  `coercible` at all, so a `to_decimal` that genuinely fails on garbage text in that
  same chain no longer quarantines the row. That is the mechanism's existing trade —
  `nullif` has it too — and it is stated here rather than discovered later.
- **The self-rate requirement is documentation, not a check.** A feed with no `USD→USD`
  row nulls every row already in the target currency, and bloomery cannot see the feed.
