Executed on branch `feat/semantic-proof-ir`. §13's first phase: proof objects and
provenance, with the rollup answer RFC 0037 already returns expressed in them. No guardrail
is deleted and no request changes outcome, which is what makes §10's parity tests mean
something.

**Drift count: 0.**

Where building this disagreed with the design for it, written at the moment it happened.
Nothing here is revised afterwards to agree with what was later settled, and nothing here
has been folded back into the RFC's text. Rows proposed below are put forward for the
author to accept or refuse; execution does not write them into a decision table itself.

## D-110 — `explain` cannot render proofs yet, and §13 assumes it can

```divergence
decision: RFC 0039 §13 — proof objects and provenance first, with `explain` rendering them for requests the planner already accepts
grade: UNLISTED

claim: the planner never consults the semantic package, so there is no proof for `explain` to render; `qualify_as_of` in the mart flattener is the module's only consumer in the tree, and wiring the planner to the grain model is RFC 0040's stated scope rather than this document's
evidence: `grep -rn "bloomery.semantic" src/ | grep -v "^src/bloomery/semantic/"` -> `src/bloomery/marts/flatten.py:60` and one docstring reference on line 190
action: decided
proposal: §13 splits its first phase in two — the vocabulary and the rollup proofs land here, and `explain` renders them in RFC 0040 where the planner first holds one. Phasing the rendering separately costs nothing: §10's parity tests are about capability being unchanged, and capability is unchanged either way
```

- Recorded **before** the code rather than found by the audit afterwards. The previous
  branch narrowed RFC 0038's scope for equally good reasons and logged nothing, and the
  self-audit had to raise it as D-108; the cost of that was not the narrowing but the
  silence.
- A consequence worth stating separately, because it is a finding about the tree rather
  than about this RFC: `planner/explain.py` emits safety notes as prose — `additive — sum`,
  `non-additive ratio — recomputed at the requested grain, not summed` — with no derivation
  behind them. §7 refuses exactly that ("no separate prose-only explanation engine"), and
  converting it needs the planner holding proofs, so it is named here and left alone.

## D-111 — a proof is built on demand, never retained

```divergence
decision: RFC 0039 D7 — whether a proof is retained after acceptance or discarded once the obligation closes
grade: OPEN
class: discovery
at: 2026-09-05T15:58:00Z
attempt: 1
claim: the question does not arise in the shape the row expects. `can_roll_up` already constructs a proof and returns it, and nothing stores one on ProjectIR, so a compile pays nothing for proofs it does not ask for and `explain` obtains one by asking the same function the planner will. The row's stated risk — holding every proof for a large project is an unmeasured cost — is zero by construction rather than by measurement, because there is no holding
evidence: src/bloomery/semantic/closure.py:405-410
action: decided
proposal: D7 closes as "built on demand, never retained". A retention flag is not needed and would be the wrong shape: it would make the proof a property of the compile rather than the answer to a question, and the question is what `explain` and RFC 0040's planner both ask
```

## D-112 — rule IDs are append-only, and a split mints new ones

```divergence
decision: RFC 0039 D8 — what happens to a rule ID when a rule is split or subsumed
grade: OPEN
class: spec-gap
at: 2026-09-05T16:00:00Z
attempt: 1
claim: the row requires this decided before the first ID ships and gives no candidate; the repository already has the answer in two places it applies to identifiers that outlive their definitions — RFC decision rows are append-only and superseded rather than edited, and retired RFC numbers are never reused
evidence: `grep -n "append-only" .claude/skills/rfc-writer/SKILL.md` -> `- **The decision table is append-only.** A superseded row stays, marked superseded, naming the row that replaced it`
action: decided
proposal: D8 closes as "append-only, by the same discipline the decision tables use". A rule ID is never reused and never silently repointed; splitting a rule mints new IDs and leaves the old one in the registry marked superseded, naming its replacements. The registry is a module constant a test asserts against, so a removed ID fails rather than disappearing — which is the half a convention cannot enforce
```

## D-113 — the shared grain corpus had one provable question, and it hid a dropped premise

```divergence
decision: RFC 0039 §10 — mutation and adversarial tests that remove one premise and require refusal
grade: UNLISTED
class: discovery
at: 2026-09-05T16:40:00Z
attempt: 2
claim: §10 asks for a test that removes a premise, and the obvious form of it — assert the proof carries a premise per determinant of the target — is vacuous against the corpus as it stood: of five questions only one is provable and its target has a single determinant, so the assertion compares one to one and a proof truncated to its first premise passes. A proof that omits determinants still renders, still serializes, still reports `closed`, and claims the rollup on less than it stands on
evidence: `uv run python -c "...for s,t in QUESTIONS: print(can_roll_up(s,t,CORPUS))"` -> one RollupProof with 1 determinant, four RollupRefusals
action: decided
proposal: none for RFC 0039's text — §10 asked for the right test and the corpus could not answer it. The corpus gains a provable composite-grain question, which strengthens the closure tests and the determinism guard that read the same tuple, and the parity assertion matches determinants by identity rather than by count
```

- **The second assertion was wrong too, and in a way the first sabotage would not have
  caught.** Written as "rebuild what `_determined_proof` would have produced and compare",
  it compared that function against itself: any wrong notion of *reached* would have been
  reproduced on both sides and passed. It now reads the column off the conclusion's
  operands, which is a fact about the proof rather than a re-derivation of it.
- Found by sabotage rather than by review, and the tell was the one worth recording: the
  mutation changed nothing, which is not evidence that the code is right.
