## Plan

P2 is the declaration and the refusal: `rollup_of:` and `keep:` on the marts
document, the IR and resolution that build a rollup from its parent, D5's
refusal wired to P1's `prove_mart_rollup`, row 14's exclusion from
`measure_owners` and the planner's covering-mart search, and an ordinary derived
gold model on SQLMesh and dbt. D6's acceptance lands here: a semantic-corpus
case and an execution-tier comparison against the same request computed from
silver.

Out: Cube `pre_aggregations` and §9's third risk (P3), MetricFlow, `assert:` on
a rollup, chained rollups (row 10 refuses them), and anything that makes a
rollup planner-selectable (row 14, and §4 leaves the choosing to RFC 0040).

## Self-audit — 2026-09-09

Whole branch at the time of the sweep: 3 commits, 231 files, +2337-192 — the
spec key, `RollupIR` and the version bump, the lowering and its refusals, both
emitters, the diff and the evidence surface, a fixture with goldens on two
targets, a corpus case, an execution comparison, this log, and the reference
page. Ten passes, then a twelve-mutation sabotage sweep over five files, then
patch coverage with the full test profile.

Five findings, all fixed on the branch.

**1 · A rollup's partition column was typed against the parent's whole
schema.** `partition_by: [years(ordered_year)]` on a rollup keeping only
`ordered_month` emitted `time_column ordered_year` for a table with no such
column — a model that compiles and fails on its first run, which is the
degradation RFC 0008 D3 refuses. The parent's other columns are *by definition*
the ones a rollup drops, which makes the parent the one schema this must not be
checked against. Logged above; the types now come from the kept columns.

**2 · dbt's rollup model was emitted by nothing.** §12's P2 asks for a derived
gold model on SQLMesh *and* dbt, and only SQLMesh's fixture was in a golden
matrix. Patch coverage named the four lines; `rollup_mart` is now in the dbt
matrix too, which is also what checks that the two targets differ only in the
envelope around one aggregate.

**3 · `_diff_rollups` had no test at all.** Seven uncovered lines, every one a
branch that only runs when a rollup changes — so `plan()` reported a rollup
being added, dropped or redefined and nothing asserted any of it.
`tests/unit/test_plan/test_rollup_changes.py` covers the four outcomes and pins
the one that is easy to get wrong: a dropped rollup is not a dropped measure.

**4 · A sabotage survived, and it named an untested capability.** Asking the
obligation with the *parent's* measure list instead of the rollup's left every
test green — because no test had a rollup carrying a subset. That subset is the
entire reason `measures:` is declarable: a mart with one `distinct_count` would
otherwise have no provable rollup, however much of it is additive. One test,
and the sweep went from 11 of 12 to 12 of 12.

**5 · Prose.** The rollup lowering claimed to be "the first aggregate bloomery
puts in a model", which is false — the quality mart counts and a reconcile model
compares totals. The true and narrower claim is that it is the first place a
*measure* is aggregated at build time rather than at query time. A refutation
was also said to render over four lines when it renders over up to five.

**Verification.** `just quality -s` 9/9. `just test` 4349 passed, 5 skipped.
`just coverage` 98.95% global against a floor of 98, guardrails 100%, steps
92.5%. `just build-docs` clean. Patch coverage 100% (149/149 added lines) on the
full profile. Sabotage: twelve mutations across `marts/rollup.py`,
`spec/marts.py`, `emit/lower/rollups.py`, the SQLMesh envelope and `plan/diff.py`

**Residue — checked and deliberately unchanged.** `assert:` on a rollup is out
of this phase and would be worth having; the shape it needs is a bound-type
lookup taking a relation's columns rather than a `MartIR`. MetricFlow and Cube
emit nothing for a rollup, which is correct for P2 and is P3's to change for
Cube. And the thing this phase cannot test at all is the one §9 warns about:
whether Cube's own query-time matching would use a pre-aggregation this
obligation did not prove. That is P3's, and RFC 0043 owns the measurement.

## Review round 1 — 2026-09-09

Three findings on PR #97, all fixed on the branch. One came from a reviewer, two
from re-reading the branch while the checks ran.

**1 · A repeated `measures:` entry emitted two columns of one name.**
`RollupMart.measures` accepted duplicates, `lower_rollups` sorted without
deduplicating (unlike `keep`, which does both), and `rollup_select` builds one
aggregate per entry — so `measures: [revenue, revenue]` rendered
`SELECT ordered_month, SUM(amount) AS revenue, SUM(amount) AS revenue`, which
neither engine accepts. Refused at the spec layer rather than canonicalized in
lowering, for the reason `keep` gives: canonicalizing is right for a library
caller and wrong for a document a person wrote. Reported by a reviewer on
`spec/marts.py`; reproduced through `rollup_select` before the fix.

**2 · A rollup carrying no measure was refused with a fact about the parent.**
`measures:` defaulted to `()`, which is how a first rollup is most likely to be
written. The obligation is asked with the rollup's measures substituted onto the
parent, so an empty list made R013 report `mart 'items' carries no measure` —
true of the object it was handed and false of the mart the author wrote, which
does carry `revenue`. `measures` is now `min_length=1`, so the refusal comes
from the spec layer, names the field, and says what is missing.

**3 · A lowering refusal addressed `marts.<name>`, which nobody wrote.** The
stage built `marts: marts.{name}` while the author declared the rollup under
`rollups:` — and the spec layer, which derives the path from the pydantic
location, already said `marts: rollups.monthly.measures`. So the two layers
disagreed about where to send an author. This is the same defect that ruled out
putting a rollup into `marts:` as a discriminated union (`marts.m.wide.…` names
a `wide` nobody wrote); it survived the restructure in the one place the path
was built by hand. Both layers now agree, and a test asserts they do.

**Verification.** `just quality -s` 9/9. `just test` 4353 passed, 5 skipped.
`just build-docs` clean. The `marts` JSON-schema golden moved: `measures` gains
`minItems: 1` and joins `required`.
