claim: §5.2 says an exposure's requirement applies transitively to "the marts and metrics it names" and §6 says a metric "two hops down" is named in the refusal, but neither says how a metric's facts are reached. The shared metric-to-mart rule `measure_owners` exists and is public precisely so the emitter and the planner cannot disagree, but it is unreachable from here — `bloomery.emit` sits above `bloomery.guardrails` in the layers contract, so importing it is a contract violation rather than a style question — a lower layer index is a higher layer, and `measure_owners` is defined at src/bloomery/emit/lower/marts.py:233

action: decided
proposal: ASSUMED — an exposure's requirement on a metric is checked against **every mart carrying that metric as a measure**, not against the one `measure_owners` would pick. `measure_owners` answers "where is this measure emitted"; the exposure's question is "can the number this dashboard reads rest on something nobody wrote down", and the planner selects a covering mart at request time that need not be the cheapest one. Requiring all of them is the only quantifier under which the exposure's guarantee actually holds. It is deliberately a different quantifier from `weak_bases`, where one fully-`LOCKED` route acquits a column: a route is an alternative *proof* of one fact and the strongest wins, while a mart is a runtime *selection* among relations and the weakest governs

## Self-audit — 2026-09-13

Scope: the whole branch against `main` — 1 commit at the time of the sweep, 8 files,
+573/−42 (`audit_scope.py scope --base main`). Sabotage before coverage, thirteen mutants
over `guardrails/evidence.py` and `spec/exposures.py`, run against the four suites that
touch them. First pass **6 killed / 6 survived**; every survivor was explained rather than
assumed, and five of the six were real gaps.

| # | Survivor | Why | Status |
|---|---|---|---|
| 1 | `_reads` admits marts absent from the draft | Equivalent — `_weak_columns` already returns nothing for a mart it cannot find, so the filter was a second guard no test could distinguish from its absence | **Filter deleted.** Dead code, and the docstring now points at the function that owns the case |
| 2 | Metric hop stops at the first mart carrying it | `draft.marts` is name-ordered and `order_items` (the weak one) sorted before `order_items_direct`, so "first" and "every" gave the same answer | **Fixture renamed** to `direct_revenue` so the strong mart sorts first, plus a direct `_reads` test where ordering cannot hide the set |
| 3 | Direct `depends_on.marts` hop dropped entirely | The one strict exposure in the fixture names *both* a mart and metrics on it, so the metric hop reached the same mart | **`finance_extract` made strict** — it names only marts, so it is the exposure with only the direct hop to lose |
| 4 | Metric never named in the message | Not a real mutant: `"" or X` evaluates to `X` in Python, so the mutation was a no-op. Replaced by one forcing the parenthetical empty, which is killed | Equivalent by construction |
| 5 | `source_path` points at the mart | Nothing asserted it. A reader sent to the mart's line would edit a mart that is perfectly happy | **Assertion added** on the leaf's `source_path` |
| 6 | The two exposure templates swapped | Every assertion in the file passed on either template — both name the mart and the metric | **Two tests added**: one pinning the imported template's artifact and repair, one reaching `EXPOSURE_MESSAGE` through the pre-regrade table, which is the only route to it |

Second pass, with the mutant set corrected and extended to thirteen: **12 killed, 1
equivalent** (the no-op above).

Two findings the sweep did not produce, from the read-through:

- **`_leaf` earned nothing.** A one-line wrapper over `str.format` whose docstring argued
  that it kept four call sites honest, enforced by nothing and indistinguishable from its
  absence under sabotage. Deleted; the four sites format their own template, which is what
  the code did before the wrapper.
- **The index one-liner was carrying status.** The live-root note was written into
  `INDEX.md`'s routing description, which that file's own rule reserves for what an RFC
  *is*. Moved to the document's status line, where the rule puts it.

Residue — what was audited and is still not certain:

- The quantifier in the first proposed row is a *design* choice, not a proof. It is right
  under the reading that the planner may serve a metric from any covering mart; if request
  planning is ever constrained to the emitter's choice, the cheaper rule becomes correct
  and this becomes needlessly strict. The test names the alternative it rejects, so the
  change would arrive as a failing test rather than as a silent drift.
- No fixture exercises an exposure whose metrics resolve to marts in *two different*
  projects' worth of shapes — the corpus has one mart plus the synthetic second. The rule
  is asked directly instead, which is what `weak_bases` already does for the same reason.
- `EXPOSURE_MESSAGE` remains unreachable from any project a person can write, exactly as
  `MESSAGE` is (row 16). Row 18 discharged that for the *imported* case only, and this
  phase inherits the same limit on the second consumer.

## Rows proposed to RFC 0065

Three, none appended — the decision table is the author's. Each is the `proposal` line of
the entry above it, with the evidence that produced it.

1. **A metric named by an exposure is checked against every mart carrying it as a measure**,
   not the one `measure_owners` would pick — a different quantifier from `weak_bases`, and
   deliberately so. See the first entry above.
2. **A mart carrying its own `locked` is skipped by the exposure walk.** One problem, one
   refusal. See the second entry.
3. **The second consumer gets its own two message templates** rather than a consumer noun
   templated into the existing two, because the docs-floor guard quotes the literal
   segments. See the third entry.
