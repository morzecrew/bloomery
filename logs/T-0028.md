## The word `distinct_count` requires the aggregation it names

```divergence
decision: unlisted
grade: UNLISTED
class: spec-gap
at: 2026-09-08T18:55:00Z
attempt: 1
claim: §4 says a DistinctCount "carries the counted identity" and is never additive across partitions, and says nothing about what the authored declaration must carry; a `distinct_count` metric with `agg: sum` would be an additive measure wearing a non-additive word, and a `count_distinct` under `additive` is already refused by D2's allowlist with a remedy that today names a route no author can take — `non_additive with a derived: block`, which a plain distinct count does not have (the D-152 shape, one member later)
evidence: `grep -n 'count_distinct' src/bloomery/guardrails/additivity.py` -> the `_REMEDIES` entry naming `non_additive`; `grep -c 'distinct_count' src/bloomery/spec/common.py` -> 0
action: decided
proposal: ASSUMED — `additivity: distinct_count` requires `agg: count_distinct` and an `expr` naming the counted identity; either half without the other is `FalseAdditivityClaim`. The remedy for `count_distinct` under `additive` names this word. The measure is stored — `COMPUTED` is unchanged — and every emitter already lowers `count_distinct`, so the lowering is the aggregation MetricFlow and Cube apply at the requested grain, computed from rows and never rolled up from a coarser result
```

## `Snapshot` is not minted as an authored word; `semi_additive` is its declaration

```divergence

grade: OPEN
kind: resolved
at: 2026-09-08T18:58:00Z
attempt: 1
claim: §4 defines Snapshot as point-in-time state "requiring explicit time-selection semantics (first/last/as-of) before cross-time aggregation", and bloomery already has exactly that declaration: `semi_additive: {over: <axis>, rule: first|last}` names the axis and the selection, the emitters lower it, and corpus case 005 is what it converts — already `refused -> accepted` without a `snapshot` word. There is no request-level as-of, so a snapshot declared without a rule could only ever be refused, and the refusal already exists: D1's snapshot rule fires on the `additive` claim and names `semi_additive` as the fix
evidence: tests/fixtures/semantic_corpus/005-semi-additive-balance/expected/semantic_outcome.json; `grep -n 'as_of\|snapshot' src/bloomery/planner/request.py` -> no request-level time selection
action: decided
proposal: ASSUMED — `SNAPSHOT` stays in the closed enum (D1) and out of `RESOLVABLE`: its lowering is `semi_additive`'s, and an authored `snapshot` beside it would be one fact with two spellings, the risk D5 names and D7 removed for ratios. It is minted as syntax only if a consumer arrives that `semi_additive` cannot serve — a request-level as-of, or RFC 0058's rollup obligation needing to name the class on a measure that declares no rule. It converts no corpus case today, which under RFC 0042 D5 is the reason not to build it
```

## A distinct count enters the single-mart `SemanticPlan`, and not the composed one

```divergence
decision: unlisted
grade: UNLISTED
class: spec-gap
at: 2026-09-08T19:00:00Z
attempt: 1
claim: RFC 0041 D8 and T-0027's D-183 hold the class back from *branch* planning, and say nothing about the single-mart plan RFC 0040 publishes. `_plannable` admits only `ADDITIVE`, with the reason that a semi-additive measure is a first/last pick joined back and summed, which a plain `Aggregate` cannot state. A `COUNT(DISTINCT x)` over the scan is exactly one plain aggregate, so withholding the plan would say the vocabulary cannot state what the query computes when it can
evidence: src/bloomery/planner/semantic_plan.py:163 (`all(metric.additivity is Additivity.ADDITIVE ...)`)
action: decided
proposal: ASSUMED — the single-mart plan states a distinct count (Scan, Filter, Aggregate, Project; R008 is true of a measure computed from the mart's own rows); the composed path keeps declining it, directly and as a component, which `_projected` and `_composable` already do for every non-additive class. Branch planning of a distinct count would need a disjointness proof §4 names and nothing implements
```
