# T-0048 · Logging and the advisory channel

Executing RFC 0033 against branch `feat/logging-and-advisories` — the subset the
readiness gate left standing, scoped by the author: the logger surface (D1–D4), the
`Advisory` type with `SpecEvidence.advisories` and one live producer, and the deprecation
mechanism (D8).

Nothing here is revised afterwards to agree with what was later settled, and nothing here
has been folded back into the RFC's own text. The rows proposed below are put forward for
the author to accept or refuse; execution does not write them into a decision table
itself.

## The readiness gate fired, and what came of it

The plan gate found five unsettled decisions, four of them load-bearing, and reported
rather than executing. The author then scoped three of them out: §5.3's advisory 2
(under-specified — "strengthens" is not vocabulary this codebase uses anywhere),
§5.3's advisory 3 (no producer — `pages/docs/reference/stability.md:222` says nothing in
the release is deprecated, so the enum member would be a documented code no path can
construct, failing the RFC's own §8 census), and D9's `--verbose` (§9 Q3 defers it to an
RFC 0020 re-read nobody has done).

That leaves this branch, and RFC 0033 stays open rather than retiring.

## The RFC has no Decisions section

`rfc_index.py check` fails on `0033-observability-logging-and-a-warnings-channel.md`
today, on `main`, for exactly this reason — the failure predates this branch and survives
it. D1–D9 exist in the prose and carry no grades, so `flag-dont-flip`'s documented
fallback applies and every one of them is executed as `LOCKED`.

**Proposed, for the author to add** — the grades read off each decision's own prose,
not invented:

| # | Grade | Why that grade |
|---|---|---|
| 1 | `LOCKED` | "A grep-able invariant, testable as one." A library that installs a handler is a library that fights its embedder; reversing it reaches every caller. |
| 2 | `LOCKED` | It is RFC 0003 restated for a new surface. Reversal invalidates the determinism contract. |
| 3 | `LOCKED` | "No test may assert behaviour *through* log output" — the rule that keeps logging non-load-bearing, and the one a later change is most tempted to bend. |
| 4 | `ASSUMED` | "Two levels only, **to start**." The RFC's own wording invites a third once there is evidence for one. |
| 5 | `LOCKED` | "Nothing important is ever *only* logged" is the whole argument for the channel existing. |
| 6 | `OPEN` | The RFC says so in as many words: "the one genuinely open signature question", held until a real embedder asks. |
| 7 | `LOCKED` | "A review that finds an advisory where a refusal belongs should treat it as a defect." |
| 8 | `ASSUMED` | The mechanism is settled; "best-effort once per process" is explicitly a tolerance rather than a guarantee. |
| 9 | `OPEN` | §9 Q3 holds it open, and D9 itself says it "fixes what the flag *means* if it lands, not that it lands". |

## Self-audit — 2026-09-12

Scope: the whole branch against `main` — 2 commits, 27 files, +1497-8, merge base
`0b6bd31`. Every pass ran.

**Five findings, all fixed.** Two were reproduced red before a line moved, two came from
sabotage survivors, one from reading a test I had written against a standard stated in the
docstring of a test two functions above it.

1. **`evaluate()` let a third-party exception out.** `_divides` caught `ParseError`, and
   an unterminated string literal in a recipe `expr:` raises `TokenError` — a *sibling*
   of `ParseError`, not a subclass. `evaluate`'s contract is that a spec-level problem
   comes back as a value; the narrower catch would have broken it on the very path this
   branch added, because the narrowest refusal width now reaches a recipe expression
   before the resolver ever parses one. Widened to `SqlglotError`.

   Reproduced: `evaluate(..., catalog=<expr: CONCAT(a, 'oops)>)` →
   `sqlglot.errors.TokenError`.

2. **A refused project reported no advisories.** `_partial` never called `_advisories`,
   so a project refused at any stage came back with an empty tuple while its catalog
   still carried the dividing recipe. An advisory is derived from the *catalog*, which is
   an **input**: it is computed and correct whether or not a stage refused, and
   withholding it made `advisories` the one field on the type that is empty for a reason
   `stage_reached` cannot explain — which is precisely the objection `_partial`'s own
   docstring raises about `unresolved`, citing `logs/T-0007.md` D-031. Now reported at
   all three widths.

3. **The three-width fix was tested at one width.** Sabotage M18 removed the field from
   the middle branch of `_partial` and **survived**: my test refused at `resolve`, which
   takes the first branch. `_partial` has three returns and they are three pieces of
   code, not three readings of one. Now parametrized over resolve, typecheck and
   guardrails, each provoked from `ecom_basic` with its catalog untouched.

4. **The positional-construction test §5.1 asks for did not test what it claims.**
   Sabotage M20 inserted a field between `provenance` and `checked` and **survived**: the
   test passed seven positional arguments and stopped before the insertion point, so the
   argument that would have been rebound was never passed. It now supplies all ten
   pre-existing fields and asserts each landed where it was named — with a second test
   pinning the count, because a field appended tomorrow silently makes the call one short
   again.

5. **A grep standing in for a behaviour.** `test_the_runtime_and_planner_stay_off_the
   _info_budget` read the module source and asserted `"_LOG.info(" not in source` — which
   is the exact objection a sibling docstring in the same file already makes about
   checking for WARNING records by grep ("a call reached through an alias would pass").
   Replaced by provoking a real hydration miss and reading the records a caller would
   see, at DEBUG and at INFO.

**Deliberately not applied.** §4 calls the CLI "the first consumer" and D9 designs

**Residue.** Three things this branch does not settle.

- **A pre-existing crash it did not introduce and does not fix.** `resolve/build.py`'s own
  `parse_one(recipe.expr)` is unguarded, so a malformed recipe expression escapes
  `evaluate()` as a raw `sqlglot` exception on `main` today — verified by running the
  reproduction against `main` itself. This branch's advisory pass no longer contributes a
  second such site, but the resolver's remains, and fixing it is a refusal-taxonomy change
  rather than an observability one.
- **The `bloomery.runtime` level is a decision, not a measurement.** §9 Q2 asks for the
  bench lane and this ships DEBUG on the argument that widening a level later is
  backward-compatible. If the measurement ever runs and says INFO, nothing here resists it.
- **`warn_deprecated` has no caller.** Nothing in the release is deprecated, so the
  mechanism is exercised only by its own tests. That is the state `stability.md` describes
  and the reason D8 exists, but it does mean the first real deprecation will be the first
  time the helper is called from library code.
