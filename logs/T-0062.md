# T-0062 · Declared source timezone (RFC 0074)

Executing RFC 0074 against branch `feat/declared-source-timezone`. §12 names three commits:
the declaration, then the rule, then the merged-entity case and the docs — "the declaration
before the refusal, because a rule that refuses before anything can satisfy it makes every
project uncompilable for one commit".

## The plan

### What the tree already carries

The IR holds the whole transform chain per source per target field —
`SourceFieldIR.transform: tuple[TransformStepIR, ...]` (`src/bloomery/ir/nodes.py:543-548`),
with each step's name and args. So **provenance is already derivable from the draft**: a
column whose chain contains `parse_ts` and no `to_utc` is a wall clock nothing declared, and
one whose chain contains neither was never a wall clock. Only `zone_in:` is missing, which is
what P1 adds.

All three of §5.3's consuming sites are in the draft too:

| Site | Where |
|---|---|
| a date role over a timestamp | `MartColumnIR.ref` + `source_entity`/`source_column` (`src/bloomery/ir/nodes.py:1083-1091`) |
| a comparison against a literal instant | `MetricIR.expr` (`src/bloomery/ir/nodes.py:1015`), parsed by `SqlExpr.ast` |
| an as-of anchor | `MartJoinIR.as_of` (`src/bloomery/ir/nodes.py:1130`) |

### The three commits

1. `ZoneName` and `zone_in:` on `SimpleFieldMapping` and `KeyField`, carried to
   `SourceFieldIR`, cross-checked against a `to_utc` in the same chain. `bloomery_ir_version`
   17 → 18. Nothing reads it yet.
2. R018, `prove_zone_provenance`, `UndeclaredZone`, and the guard that enumerates the three
   sites. Case 011's `zoneless` arm converts. Every existing project whose parsed timestamp
   reaches one of the sites starts failing, and migrating them is part of this commit.
3. The merged-entity case — two mappings, two zones, one canonical field — and the docs pair.

## Decisions taken before acting

The zone-name validation question is the one the RFC's prose settles and its decision table
does not, so it is `unlisted` rather than a departure from a graded row.

```divergence
decision: unlisted
grade: UNLISTED
class: spec-gap
at: 2026-09-17T00:35:00Z
attempt: 1
claim: a zone name cannot be validated against the shipped zone database without reading the filesystem, which RFC 0003 bans under src/bloomery and which makes acceptance a fact about the machine — `zoneinfo.TZPATH` is four directories and this one holds 598 zones, another holds a different number
evidence: `uv run python -c "import zoneinfo; print(zoneinfo.TZPATH); print(len(zoneinfo.available_timezones()))"` — `('/usr/share/zoneinfo', '/usr/lib/zoneinfo', '/usr/share/lib/zoneinfo', '/etc/zoneinfo')` / `598`
action: decided
proposal: ASSUMED — a zone name is validated by shape, not against a zone database. `to_utc`'s zone argument reaches SQL unvalidated already (`src/bloomery/transforms/_builtins.py:521-527`), so the engine is the zone authority for the spelling that is *used*; validating the spelling that is merely *declared* against a database would make a spec compile on one machine and be refused on another, and would put the stricter check on the weaker claim.
```
