## D-075 — what a project with no statable start gets

```divergence
decision: RFC 0054 D5
grade: OPEN
class: discovery
at: 2026-09-04T14:40:00Z
attempt: 1
claim: §5.3 offers three answers for a project that backfills by time and declares no date dimension — a config with the key commented, no config at all, or a refusal — and ranks none
evidence: src/bloomery/emit/sqlmesh/__init__.py:849
action: decided
proposal: no `config.yaml` at all for that project, which is today's behaviour exactly; the emitter returns `None` and the artifact is absent rather than incomplete
```

- **Touches:** RFC 0054 D5 (`OPEN`) — answered, not departed from.
- **Decided:** `_config_artifact` returns `None` when the start cannot be stated *and*
  something reads it. Two of the three cases still get a file: a project with a date
  dimension gets `dialect` and `start`, and a project that backfills by time nowhere gets
  `dialect` alone, because nothing there reads a start.
- **Because:** the RFC's own goal sentence decides it — "the emitted config states every
  value it contains and contains no value bloomery cannot state". A file whose missing
  start makes `sqlmesh plan` succeed over a single day is the M4 failure re-created one
  level up: it *runs*, which is worse than a directory that does not. The commented-key
  option was rejected for exactly that reason rather than for being untidy — a comment is
  read once and the plan is run every day. A refusal was rejected as disproportionate: it
  would refuse a project that compiles today over a file that did not exist yesterday.
- **Consequence:** the artifact set is a function of the catalog for the first time, which
  is stated in the emitter's docstring because "sometimes there is a config" is otherwise
  a surprise a reader meets in a diff.
