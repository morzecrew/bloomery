# T-0033 · The rollup obligation

Executed RFC 0058 P1 against branch `feat/rollup-obligation`.

**Drift count: 0.**

Where building this disagreed with the design for it, written at the moment it
happened. Nothing here is revised afterwards to agree with what was later
settled, and nothing here has been folded back into the spec's own text. The
rows proposed below are put forward for the author to accept or refuse;
execution does not write them into a decision table itself.

| Class | Test | Meaning |
| --- | --- | --- |
| `discovery` | Could not have been known before code existed | Healthy — the spec was right to be silent |
| `spec-gap` | Could have been known; the spec was silent or at the wrong altitude | The design process missed something |
| `drift` | The spec covered it and it was built otherwise anyway | **A defect** |

## Plan

P1 is the obligation as vocabulary: `prove_mart_rollup` and rule R013 under
`semantic/`, answering per measure whether a rollup keeping a given set of the
parent mart's dimensions may carry it. Row 13 fixes what P1 admits — `additive`,
and `ratio` over operands the rollup carries and P1 itself admits.

Out: the `rollup_of:`/`keep:` spec surface, the IR, resolution, the guardrail
that refuses (D5's wiring, as opposed to D5's answer), row 14's exclusion from
`measure_owners`, both derived-model emitters, Cube `pre_aggregations`, and
D6's corpus and execution-tier acceptance. Those are §12's P2 and P3.

One thing this phase deliberately does not do is reach the compile path. §9's
first risk is that the feature gets built early because it looks like an emitter
feature, and the mitigation is to build the invisible half first and where it
can be read. Nothing here is consulted by `evaluate()`, no IR node gains a
field, and no artifact byte moves.

## Self-audit — 2026-09-09

Whole branch: 2 commits at the time of the sweep, 9 files, +1113/-6 —
`semantic/rollup.py` (new), the R013 registry entry, the package export, the
test module, a `mart()` builder in the grain-model support, RFC 0058, the index,
and this log with its task file. Ten passes, then a hand sabotage sweep, then
patch coverage over the added lines with the full test profile.

Six findings, all fixed on the branch. Four of them are one shape: a rule stated
in one place and not applied in the other place that needed it.

**1 · The per-measure entry point proved a rollup that groups by nothing, and
then one that groups by a column the mart does not have.** `prove_measure_rollup`
is public and its class question never reads `keep`, so every check on the
grouping lived in `prove_mart_rollup` — the entry point that happens to compose.
A caller reaching the other one got a proof for a rollup that is not one. Found
twice: the empty case first, and the unknown-dimension case only after the fix
for the first was written and read back, which is the same hole with a different
input. Both now go through `_grouping_refusal`, which both entry points call.

**2 · The ratio's proof cited R008 for the quotient itself.** A ratio is
calculated from measures the mart stores and is not stored, so concluding
`EmbeddedAtMartGrain` about it claimed something the mart never does. The
premises are now the operands' proofs alone, each carrying its own mart
contract — which is R012's argument stated as a tree, and how
`prove_ratio_reconstruction` already premises.

**3 · `_UNSUMMABLE` was a name whose own comment had to argue it away.** `RATIO`
mapped to `None` and a ratio is never summed, so the mapping needed a paragraph
saying its name did not mean what it said. Renamed `_REFUSALS` / `_ClassRefusal`,
which is true for all six members, and the paragraph became one sentence about
admitted not meaning summed.

**4 · No CHANGELOG entry.** R011 and R012 landed as pure vocabulary that nothing
in the pipeline consulted, and both got one; this had none. Added.

**5 · A sabotage survived, and its reason was the finding.** Disabling the
grouping guard in `prove_mart_rollup` left every test green — because finding 1's
own fix had just given that path a second guard one call down. What the composing
guard still decides was untested: the refusal names *no* measure rather than
whichever sorted first, and it outranks `no_measures` when both are wrong at once.
Two assertions, and the sweep went from 11 of 12 to 13 of 13.

**6 · Prose.** The escape-hatch paragraph said the obligation "exists to be" the
second source of truth it exists to avoid; `prove_measure_rollup`'s docstring
still described an order that finding 1's fix had changed; the empty offer list
rendered as `offers ` and now says `offers none at all`. And in the authoring
commit, the status line said RFC 0037 and RFC 0040 had "landed and retired" —
they have landed and are deliberately *not* retired, and this document is one of
the dependants keeping them. Corrected before the commit left the branch.

**Verification.** `just quality -s` 9/9. `just test` 4261 passed, 5 skipped.
`just coverage` global 99.1% against a floor of 98, guardrails 100%, steps 92.5%.
Patch coverage 100% (74/74 added lines) measured with the full profile, so no
detection branch here is dead. Hand sabotage: 13 mutations, 13 killed, the file's
checksum verified back to pristine after the sweep.

**Residue — checked and deliberately unchanged.** `_metric` is a two-line lookup
duplicated from `semantic/additivity.py`; extracting it means exporting a private
name across sibling modules or minting a module to hold four lines, and neither
is cheaper than the repeat. A mart's dimensions include the columns its measures
read, so a rollup may `keep` one; it groups by a column that exists and nothing
is unsound, and the place to refuse it is the `keep:` spec surface P2 builds. And
what this phase does not test at all is a rollup: nothing declares one, nothing
emits one, and the execution-tier comparison against silver that would show the
obligation is the *right* one is D6's, in P2.

**Drift count: 1.** The `drops_nothing` case above, found in review rather than
by the audit, and classed `drift` because the plan reached it, weighed it against
§1's definition and went the other way.

Three findings from review, all fixed. They are recorded here rather than as
divergences because none of them contradicts a decision — they are guards the
obligation needed and did not have.

**7 · A measure the mart does not carry was certified.** `prove_measure_rollup`
never checked `metric.name` against `mart.measures`. The module already held the
position for ratio operands — `operand_not_carried` refuses rebuilding a
quotient from something the rollup does not store — and did not apply it to the
measure itself, because the composing entry point iterates `mart.measures` and
so could never produce the input. The fourth instance on this branch of one
shape, and the second after a memory rule was written about it.

**8 · An `additive` metric with no aggregation was certified.** `additive` is a
claim about a measure and such a metric has none to make it about.
`_has_no_measure` in `guardrails/metrics.py` names the shape and refuses it only
under `cumulative:`, its docstring saying the rest reaches the emitter — so it
arrives here declared additive with nothing to sum. Refused below the class
question, so a `distinct_count` with no aggregation still gets the more specific
class refusal and a ratio, which legitimately has no aggregation of its own,
never reaches it.

**9 · Row 13 read as a shorter list than the code.** It omitted `snapshot` from
the refused classes. `SNAPSHOT` is not in `RESOLVABLE` so no project can mint
one, which is a reason for the mapping to carry it for totality and not a reason
for the row to say less than the module does. Row 15 supersedes it, and carries
the operand correction this log already proposed.

One claim was refuted rather than fixed: that the status line and D2 contradict
each other. They do not. D2 records what the block *was* and why the feature
waited eight RFCs; the status line records that the condition is now met. A
precondition that has been satisfied does not become a false statement, and the
decision table is append-only — 0057's D2/D2b and 0037's D8 are the same shape,
kept and marked rather than rewritten.

**Verification, this round.** Both code findings reproduced red before the fix
