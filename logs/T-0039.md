## Plan

§12 asks for one phase and one PR. Source in the order the graph reads it: the
sixth prefix, then the node kind and its constructor, then the three edge
shapes and the builder that emits them, then the reservation's `_MINTS` row.
Tests next — the edge-vocabulary guard's constructor map is the one that fails
loudest if the node kind lands without it. Docs and the retirement last.

Out: per-column `entity_field → mart` edges (D3), a `dim_date` node (D8, and
§4's non-goals), stable mart ids (§8, RFC 0062's surface), and `plan()` (D7).

## Self-audit — 2026-09-10

Scope: the whole branch against `main` — 1 commit, 16 files, +588/−326, merge base
`0a6f9a8`. Every pass in the sweep ran; what follows is what they turned up, ranked,
with what was done about it. All six are fixed on the branch.

1. **A line no test could reach.** `build_graph` listed rollups among the unconditional
   mart nodes beside marts. It cannot matter: `MartSet` refuses a rollup whose `of:` is
   not a mart of the same document (RFC 0058 D10), so every rollup already has an
   incoming `rollup` edge by the time `build_graph` collects nodes from edges. The
   sabotage sweep confirmed it — deleting the line left 328 tests passing, the only
   survivor of thirteen mutants. Deleted rather than tested around, and the comment
   beside it now says why rollups are *not* listed. The comment as first written
   ("listed anyway rather than relying on that") was itself the tell: it named the
   reason the line was unnecessary and kept it.
2. **A refusal message nobody proved.** `_MINTS`'s second field decides whether the
   refusal for a reserved entity name says "this entity's field 'revenue' and a mart of
   that name are one id" or the weaker "mints an id in the mart namespace". Flipping
   `mart`'s flag to `False` changed the sentence and killed no test — the `source` and
   `metric` messages are pinned, the four others are not. The flag is derivable rather
   than a matter of opinion: an entity field is two segments, so a prefix collides
   exactly when its own ids are two segments. `test_collides_is_the_id_s_own_arity`
   now derives the whole table from the node constructors, so a seventh prefix cannot
   get it wrong quietly.
3. **A stale reserved-name list in the reference docs.**
   `pages/docs/reference/spec-schemas.md` still said an entity may not be called
   `canonical`, `metric`, `source` or `step` — "the four lineage node-id prefixes". It
   has been five since RFC 0056 and is six now. Corrected, with `mart.<name>` spelled
   out beside the others.
4. **Two prose claims in `graph.py` that had drifted.** `_EDGE_SHAPES` said the
   vocabulary covers "the two builders below" — there are three, plus `build_graph`'s
   own constructions — and pointed at `tests/unit/test_resolve/test_graph.py` for the
   two guards that hold it, which have lived in `test_edge_vocabulary.py` since they
   were written. The module docstring listed the graph's contents and stopped at
   metrics, having never been updated for exposures either. All three corrected.
5. **A changelog entry contradicted by the one above it.** RFC 0056's `Unreleased`
   entry said `lineage --direction downstream` "used to answer with the marts that can
   serve the metric and stop" — marts were not nodes then, which is precisely what this
   change fixes, so the sentence was false when written and unreadable beside the new
   entry. It also spelled the node id `metric:…` rather than `metric.<name>`. Corrected
   to what the walk actually did: it stopped at the metrics composed from the one named.
6. **A weak assertion in a test I wrote.** `test_a_mart_with_no_measure_and_no_rollup_still_exists`
   asserted that no edge has a `MART` *source*, which is true of `ecom_basic` whether
   or not the node exists. It now asserts that no edge touches the node at all, which
   is the claim the test's name makes.

**Verification.** `just test` 4472 passed / 5 skipped; `just quality -s` 9 of 9;
`just coverage` exit 0 with patch coverage 100% (18/18 added source lines);
`just build-docs` clean. Thirteen hand-written mutants over the new code — both edge
directions, both labels, the id substitution, the prefix, the reservation, the
unconditional nodes, the dangling-name filter — of which eleven were killed on the first
pass and the two survivors are findings 1 and 2 above; on the re-run every remaining
mutant was killed and the thirteenth's target no longer exists.

**Residue.** Three things this audit did not settle. The `dim_date` question (D8) is
deferred, not answered, and the entry above says so. Marts still have no stable id, so a
renamed mart is a deleted node and a new one — RFC 0062's surface, recorded in §8 and
unfilled. And the dimension-column gap (D3) is a real hole that will be met by whoever
groups a dashboard by a flattened column no metric reads; it is documented in the how-to
and in the builder rather than mitigated, which is the design and not an oversight.
