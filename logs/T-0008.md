## D-035 — the identity is bound in `validate_document`, not in `load_project`

```divergence
decision: RFC 0032 D3
grade: LOCKED
class: spec-gap
at: 2026-08-30T19:42:00Z
attempt: 1
claim: §5.1 says "load_project sets it at construction"; binding it there leaves every caller that reaches validate_document directly with a Mapping it cannot construct, which is 101 failing tests and a public function that cannot be called with its own model
action: decided
```

D3 is `LOCKED` and this does not depart from it — D3 says *the loader* sets the field and
that an authored value is refused, and both remain true. What moves is **where in the
loading path**, which §5.1 stated in prose and no decision graded.

Binding it in `load_project` failed immediately and widely: `validate_document(Mapping, …)`
is the shape-checking entry point, it is public, and the corpus calls it directly in
several test modules. A `Mapping` whose required field only one caller can supply is a
model that cannot be validated except through one door.

`validate_document` is the better place on its own merits, not merely the convenient one:
**it already takes `document`**, because that name prefixes every refusal raised from the
document (RFC 0002 §5.3). Binding the identity from the same argument is what stops the
coordinate a report sends a reader to and the coordinate a refusal names from being two
different values that can disagree. The refusal of an authored `document:` moves with it.

Effect on the count: 101 failures → 7.

**Proposed row.** `| 8 | ASSUMED | The identity is bound in validate_document, which already
receives the document name as the prefix for this document's refusals (RFC 0002 §5.3) —
not in load_project, which would leave a required field only one caller could supply.
Consequence: every path that parses a mapping gets an identity, including a caller that
reaches the shape check directly. Added by execution 2026-08-30 — see logs/T-0008.md
(D-035, attempt 1). |`

## D-036 — the exported schema would have demanded the key the loader refuses

```divergence
decision: unlisted
grade: UNLISTED
class: spec-gap
at: 2026-08-30T20:10:00Z
attempt: 1
claim: adding a required field to Mapping puts it in the JSON Schema `bloomery schema` exports, whose audience is a spec author — so the schema would mark `document` required while the loader refuses an authored one
action: decided
```

The RFC's scope line claims "no golden moves". `tests/golden/test_spec_schemas.py[mapping]`
moved, and it was **not a stamp to update**: the exported schema listed `document` in both
`properties` and `required`. That schema exists for an editor to validate a spec against
(RFC 0020), so it would have demanded the one key D3 refuses — the exported contract
contradicting the compiler, on the surface whose whole job is to agree with it.

Decided: `document: SkipJsonSchema[str]`. The schema describes the **authored vocabulary**,
and D3 already says this field is not part of it; the annotation makes that true on the
exported surface rather than only in prose. The golden then does not move, and the RFC's
scope line becomes true rather than nearly true.

This is `spec-gap` rather than `discovery`: RFC 0020's schema export is a documented public
surface and §3 could have named it. It did not, and §6's test list had no case for it.

**Proposed row.** `| 9 | LOCKED | document is SkipJsonSchema — absent from the schema
bloomery schema exports. That schema's audience is a spec author and D3 says this field is
not theirs to write; a required document there would have an editor demand the one key the
loader refuses. Consequence: the model and the exported schema deliberately disagree about
one field, which test_document_is_in_the_model_and_not_the_schema records where the other
measured divergences live. Added by execution 2026-08-30 — see logs/T-0008.md (D-036,
attempt 1). |`

## D-037 — `FieldProvenance` sorts by `(entity, field, mapping)`

```divergence
decision: RFC 0032 D7
grade: OPEN
class: discovery
at: 2026-08-30T20:35:00Z
attempt: 1
claim: D7 delegates the sort order and says to decide it against the corpus rather than reason about it
action: decided
```

D7 is `OPEN` and asks execution to look at `multi_source`'s four recovered facts and pick.
Looked at:

```
order_line.quantity   mapping_legacy
order_line.quantity   mapping_platform
order_line.sku        mapping_legacy
order_line.sku        mapping_platform
```

`(entity, field, mapping)` keeps a field's two answers adjacent, which is the comparison a
reader of a merged field is making — *how is `quantity` built, and do the two documents
agree?* `(entity, mapping, field)` groups by document and interleaves them, so the two rows
that exist to be compared sit apart with another field between them.

Decided as §5.4 argued, and the argument survives contact: the report is read per field,
not per document. Recorded here because D7 asked for the look, and the look is the evidence
— the prose alone would have been a preference.
