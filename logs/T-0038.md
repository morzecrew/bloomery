## Plan

Three phases as §12 orders them, plus a fourth commit for §7's docs. The spec
kind, the IR node, the fifth node-id prefix and D2's refusal first — §12 calls
the graph the product of that commit, and it is the half that has to be right
before an artifact is written from it. Then `models/exposures.yml` with its
golden and its `dbt parse`/`dbt ls` leg, then `affected_exposures`.

Out: reading anything from a BI tool (D1), Cube and SQLMesh artifacts (D4),
a warning for an unexposed metric (D5), URL validation (D6), MetricFlow
`saved_queries` (§10), and ownership as a general annotation (§8 — RFC 0055).

## Self-audit — 2026-09-10

Whole branch, 7 commits / 230 files / +2000-507, against merge base `38dd7a6`.
Audited: the four source commits, the docs commit, the retirement, and the log
itself. Two probes against real dbt 1.12.3 (dbt-duckdb 1.11.0) informed the
design before the audit and were re-run inside it as the e2e leg.

**Fixed — six findings, all on this branch.**

1. **`_declared`'s empty case was unproven, and it was breaking a gate.**
   `guardrails/exposures.py:49` — the `(none)` a refusal ends on when a project
   declares no metrics at all — was the one uncovered added line on the branch,
   and `just coverage`'s `--include='src/bloomery/guardrails/*' --fail-under=100`
   was red on account of it. Sabotage agreed independently: replacing it with
   `""` survived the whole suite. A project may carry an exposures document and
   no metrics document; the refusal then trailed off on a bare colon with
   nothing to say the list was empty rather than truncated. Covered by
   `test_a_project_that_declares_nothing_says_so_rather_than_trailing_off`.

2. **The dbt departure's own mechanism was untested.** Deleting the
   metric-to-serving-mart resolution — the whole of what replaces §5.1's
   unbuildable `metric('…')` — survived sabotage. The reason is the finding:
   `ecom_basic`'s two exposures each name the serving mart *directly as well*,
   so the two contributors to that `ref()` set produce the same reference and
   either alone satisfies the golden. Two tests isolate each contributor: a
   metric-only exposure that can reach a `ref()` only through its mart, and one
   naming a metric no mart serves, which reaches `meta` and emits
   `depends_on: []` — measured to parse.

3. **`ExposureIR.kind` was a bare `str`** where every other closed vocabulary
   in that module is an enum. The IR's builder is its validator (RFC 0003 D1),
   so a hand-built node was free to carry `report` — a type the dbt emitter
   would write out and dbt would refuse. Now `ExposureKind`, lowered with
   `ExposureKind(exposure.kind)` exactly as `Additivity` is.

4. **A silent drop where this file's idiom is `guaranteed`.** The emitter
   filtered `exposure.marts` by `if mart in by_name` — a state D2 refuses, so
   the filter could only ever fire if that refusal had stopped working, and it
   would then emit an exposure short one `ref()` with nothing to say so.
   Replaced with `guaranteed(...)`, which is what `_mart_artifact` twenty lines
   up already does for its own guardrail. The same edit removed a
   `by_name[mart].name` round-trip that read as a resolution and returned its
   own argument.

5. **A docstring said the opposite of the function it named.**
   `_build_exposures` claimed `check_exposure_targets` is "asked over the
   finished draft"; that guard's entire module docstring argues it must *not*
   be, because a mart absent from the draft may have failed to flatten rather
   than failed to exist. Corrected. `exposure_node` called an exposure "the
   graph's only sink", which is false as written — a metric with no dependants
   is a sink too. It is the only node kind nothing is ever *downstream of*, and
   it now says that.

6. **§6's CLI leg was silently dropped.** The RFC asks for
   `lineage … --direction downstream --format json` carrying the exposure,
   "since the JSON is the surface a script reads". The behaviour worked;
   nothing pinned it. Now pinned, on the walk the feature exists for.

**Two more, filed as entries above rather than here:** §5.2's delegated
reservation question was answered in code and not logged (the entry immediately
above this section), and `VERSION_KEYS` was exported in `schema.__all__` while
its sibling `JSON_SCHEMA_DIALECT` — reached the same way, by the same tests —
is not; it was removed from `__all__` to match.

**Residue — what I would still distrust.**

- **The e2e leg runs nightly, not per-PR.** `dbt ls --select +exposure:*` is the
  only check that dbt accepts this artifact, and CI runs the e2e tier on the
  Docker lane. A change to the emitted shape goes green on a PR and red the
  next night. That is every e2e test's position here, not this one's alone.
- **`meta.bloomery_metrics` is a bloomery convention nothing else reads.** It
  records what the mart refs lowered away; no tool consumes it, so nothing
  would notice if it stopped being written except the unit test that pins it.
- **The exposure/mart edge that does not exist.** Recorded as an entry above and
  built deliberately, but it means `lineage --direction upstream` from a
  mart-only exposure returns the node and no edges — truthful, and less than a
  reader expects from a walk. The dbt artifact and `plan()` both see the mart
  dependency; only the graph does not.
- **Nothing diffs an exposure against itself.** Entry above. A dropped or
  re-owned exposure produces no `Change`.
