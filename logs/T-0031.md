## Self-audit — 2026-09-09T10:20:49Z

Whole branch, 1 commit / ~430 lines before the audit's own fixes: 5 source files, 3 test
files, 4 documents, 1 task file. Scope from `audit_scope.py scope --base main`.

**Eight findings, all fixed.** Three came from sabotage survivors and one of those
survived a second time, against the fix written for it.

### 1. A test that asserted nothing about the branch it named (fixed before commit)

`test_a_plan_without_a_semantic_half_prints_no_evidence_heading` was written as
`assert replace(query, semantic=None).semantic is None` — a tautology about
`dataclasses.replace` that never ran the CLI and could not fail if the renderer printed
a heading over nothing. Rewritten to monkeypatch the planner and assert against the real
output, then verified red: with the `is not None` guard removed it fails `3 == 0`.

### 2. "Routinely share a leaf" was never observed (fixed)

`render_evidence_grades`'s docstring justified deduplicating facts across proofs by
saying two proofs of one plan routinely share one. Measured instead of assumed: a
cross-mart request yields three proofs and **four distinct leaves of four**. The dedup is
right and the reason was invented. The docstring now says what is true — that no plan in
the corpus produces a duplicate, and the dedup is there because a tally that counted one
declared fact as two would lie about the one number this phase exists to produce.

### 3. The renderer was tested on the simplest possible input (fixed)

One fact is not a walk. A cross-mart plan carries three proofs and four facts — and it is
the only plan in the corpus that grades **two ways**: each measure is `LOCKED`, each
branch's one-row-per-key fact is `ASSUMED`, derived by the planner from the aggregate it
just built. That contrast is the feature, and it was neither tested nor documented; the
docs example showed `Evidence (1 locked)` while the prose explained a word the reader
would never see.

### 4. `explain` shows no evidence at all for a derived metric (documented)

`QueryPlan.semantic` is `None` for a derived metric — a different planning route builds no
semantic plan — so the section silently does not appear. The CLI already prints nothing
rather than an empty heading, which is the right behaviour; what was missing is that
nothing said so, and a reader meeting a plan with no Evidence section would read it as a
plan resting on no facts. Now in the docs.

### 5. The allowlist claimed more than its test proved (fixed)

The comment admitting `cli/__init__.py` to read the semantic plan said the SQL, the
columns *and* the explanation are byte-identical with the section present or absent. The
test pins the SQL and the explanation. Narrowed to what is pinned, and pointed at the test
that pins it — an exemption argued from an over-claim is an exemption nobody can check.

### 6–8. Three sabotage survivors, and one that survived its own fix

```text
SURVIVED  grades-fall-back       SURVIVED  no-dedup-across-proofs
SURVIVED  top-level-facts-only
```

**`no-dedup-across-proofs`** and **`top-level-facts-only`** survived for one reason: every
proof the planner builds is flat and shares nothing, so `leaves` and `facts` are the same
tuple and the set changes nothing. Both are exercised now on hand-built plans — one where
two proofs rest on the same fact, one where a fact sits under a premise, which is the
shape R011 and R012 produce and nothing yet plans.

**`grades-fall-back`** replaced `_GRADES[self]` with `.get(self, ASSUMED)` and survived —
`test_every_provenance_has_a_grade` passes identically against both, because every member
is mapped and a default never fires. That test is D7's guard and could not tell a total
mapping from a defaulting one, which is precisely the ritual §9 warns it must not become.

**It then survived the fix.** The first attempt asserted `_GRADES[absent]` raises — which
tests the mapping and not the property the mutation changed. The second monkeypatches a
row away and calls `Provenance.DERIVED.grade`, with a control asserting every other member
still answers. Re-swept: **10 of 10 caught, 0 survived**; patch coverage 100% (25/25).

### Noted, not a defect

**`EvidenceGrade.OPEN` can never appear in a rendered plan.** A fact of that grade closes
nothing, so a proof resting on one is not closed, so `SemanticPlan` refuses to hold it.
§5.1 mints the member so the three states are total rather than because a consumer will
meet one, and the renderer skips empty tallies, so it prints nothing rather than a zero.

**Where §7's docs section landed.** No concepts page holds semantic-proof material, and
§7's worked example is a mart declaring `requires_evidence` — a key P1 does not add. The
grades are documented where a reader meets them, in the CLI how-to; the concepts treatment
belongs with P2, when there is a decision to make rather than only a display to read.

departures from what RFC 0065 decided.)

## Review findings — 2026-09-09T13:16:05Z

The PR review round on #94. Two defects fixed, two claims refused.

### 9. The guard's exemption was per file, not per read (fixed)

`_RENDERS_THE_PLAN` admitted `cli/__init__.py` wholesale, so any later `.semantic` read
in that module — including one that *generated* from the plan, which is the only thing the
guard exists to stop — would have ridden in under the renderer's exemption. It now records
how many reads the file is admitted for, and a second has to be argued the way the first
was.

Finding this exposed a second one: the count was already **2**, not 1. The `is not None`
test and the render call were separate attribute reads, so "the renderer reads the plan"
was already an understatement of my own code. It reads it once into a local now, which is
the tightest honest number and the clearer expression.

Raised by a reviewer, and the better of the two halves is theirs: a per-file exemption is
coarser than the claim it stands for.

### 10. `__all__` lost the order it had (fixed)

Inserting `render_evidence_grades` after `render_check` left `render_evidence` behind it.
The reviewer's stated reason is wrong — RUF022 is suppressed in `pyproject.toml` with a
recorded rationale, and `just quality -s` passes — but the file's list was ordered before
I touched it, and the conclusion stands without the reason.

### Refused, with the evidence

**`tasks/T-0031.json` grades D8 `OPEN` while the log calls it settled.** Both are correct
and the pair is the mechanism. A task file records the grade **in force when the work
started**, and D8 still reads `OPEN` in the RFC's table because `flag-dont-flip` forbids
amending a spec from inside a task — the entry's `proposal:` line *is* the amendment
request, for the author to accept or refuse. The grade is also what makes the log check
mean anything: my D8 entry is `kind: resolved`, `action: decided`, which is legal for
`OPEN` and would be checked differently against any other grade. RFC 0039's status line
says the same of RFC 0042 D7 while that row stays `OPEN`.

**Facts sharing a `source` with different statements are counted separately.** They are
different facts. A `SemanticFact` is `(source, provenance, statement)` and its identity is
all three, so two facts about one measure asserting different things are two things
somebody declared. Deduplicating by source would merge distinct claims and *under*count,
which is the opposite of the error the set prevents — one fact reached through two proofs
being counted twice.
