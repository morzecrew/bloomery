## Self-audit — 2026-09-11

Scope: the whole branch against `main` — 4 commits, 12 files, +628-18, merge base
`e5c7321`. Every pass ran. **Four findings, all fixed**, three of them from the sabotage
sweep or from a coverage number rather than from re-reading.

1. **A facet with no compact spelling printed an arrow pointing at nothing.** The page
   says such a facet "prints the field and stops"; the renderer printed
   `filter  filter         ->`, which reads as truncated output rather than as an absence
   of values. Found by rendering a hand-built value rather than by reading the code — the
   corpus fixtures have no filter change, so no real history produced the shape.

2. **`--catalog` was never exercised on this command.** Every evolution fixture carries
   its own `catalog.yaml`, so a `timeline` that ignored the flag entirely answered
   identically on every test here. It is the flag a history most needs — the specs evolve
   and the vertical does not — and the new test strips the catalogs out and points both
   versions at one shared file, asserting the refusal without it as well as the answer
   with it.

3. **Nothing pinned that boundaries are reported in version order.** Sorting every change
   by node passes any test that only asks which nodes appear, and it puts a later boundary
   above an earlier one — turning a history into a list of nodes. The value's order is
   version first and node within a boundary; the rendering must not re-sort it, and now
   fails if it does.

4. **`render_timeline`'s absent-everywhere branch was unreachable from the command and
   uncovered.** The command refuses before rendering it, but the function is public and a
   caller can build such a value — which its own comment claims. A claim a coverage report
   contradicts is a claim, so it is now a test rather than a comment.

**Verification.** `just quality -s` 9 of 9; `pyright src` 0 errors; `just build-docs`
clean; the unit tier 4059 passed / 17 skipped. Coverage measured per file rather than
inferred: the global total 99.1%, `cli/__init__.py` 99.7% and `cli/render.py` 98.9% before
finding 4 and with line 550 covered after it. Twelve hand-written mutants over the
command, its label handling, its refusal, its JSON and its rendering: **10 killed, 2
survivors**, both real and both findings 2 and 3 above, re-run dead after the fix.

**Residue.** Three things I would still distrust:

- **The page's CLI sample is not executed**, because it names directories a reader will
  have and this repo does not. Its *shape* is pinned against a real run — four regexes
  over the heading, a presence row, a boundary line and a facet row — which catches a
  format change and would not catch a wrong value in the sample's own columns.
- **N compiles, and nothing warns.** A caller who passes sixty directories waits for sixty
  compiles with no progress output. §9 names the cost and this command does nothing about
  it; a reader who tries it on a real history will find out by waiting.
- **The label is a path as typed, so two directories with the same basename are
  distinguishable and two spellings of one path are not.** `./q1` and `q1` are two labels
  for one version, which is a consequence of D1 rather than a defect, and nothing says so
  at the command line.

```divergence
decision: unlisted
grade: UNLISTED
class: discovery
at: 2026-09-12T06:35:46Z
attempt: 1
claim: a facet value can carry a newline and `_table` cannot hold one. A metric's `expr:` written as a YAML block scalar reaches `_render` as a multi-line string, and passing it through emits one facet as three rows — worse, the column widths are computed with `len` over the whole cell, so every other row is padded to the longest *embedded* line and the table stops being a table. The exposure is not this renderer's: `_table` is shared by every command that prints one
evidence: `uv run python -c "<render_timeline over a FacetDelta whose old is 'CASE\n  WHEN paid THEN amount\nEND'>"` -> one facet printed as 3 lines, and the `grain` row padded to 33 columns by a line that is not its own
action: decided
proposal: ASSUMED — `_table` flattens a cell that carries a line break into one spaced line, and leaves every other cell byte-identical. Fixed there rather than in `render_timeline` because the cell is shared: a newline in any caller's value breaks that caller the same way, and one guard in the shared function is a smaller diff than a guard in each. Collapsing rather than escaping, because the table is a summary surface and `--format json` carries the exact value; only a cell that carries a break is touched, so no correct caller's bytes move for a defect it does not have.
```
