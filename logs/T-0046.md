## Plan

**P2 is already landed.** §12's P2 is "the facets, which is RFC 0064's delta applied to
each adjacent pair", and that is what RFC 0064 P1+P2 built in #107: `TimelineChange`
carries `facets: tuple[FacetDelta, ...]`, populated by `facets()`. Recorded here rather
than rebuilt — a phase re-executed because a list said so produces a second
implementation of something that already works.

So this task is three things. The rows first, into RFC 0064 (D6 and five) and RFC 0069
(one), since the author accepted them and 0069 is retained rather than retired — which
is what gives its last row somewhere to live. Then the command: N positional spec
directories, `--node`, `--format table|json`, rendering beside `lineage`'s. Then the
status blocks.

Out: any change to `timeline()` itself, any change to `lineage()` (D7's second half is
its own decision), any history fetching (D2), any label parsing (D1), and a manifest
file (the entry below).

The command cannot borrow `lineage`'s answer, because `_find_node` refuses against *one* graph and a timeline has N — and a node absent from the first version is not unknown, it is the answer the page already teaches: ask by an id the project adopted later and the versions before it report absent

action: decided
proposal: ASSUMED — the command refuses only where the node is absent from **every** version, and `timeline()` itself is unchanged: a full-length timeline of absences stays the library's answer, because a caller holding the value can read the entries. The refusal carries no did-you-mean. Suggestions need a graph and this has N of them, so offering one means either compiling every version twice — doubling the cost §9 already calls the feature's main risk — or picking one version's graph and calling its spellings the project's. It names the count and points at `bloomery lineage` on a single directory, which is where a suggestion can be built from one graph that is already in hand. D7's second half, whether `lineage()` should change to match, is untouched: it answers about one instant and has no absence to report.

proposal: ASSUMED — no manifest. Positional directories only, and a shell glob is what sixty of them are for: `bloomery timeline history/*/ --node metric.gross_revenue` passes them in lexicographic order, which is the order RFC 0069 D10's recommended label spelling was chosen to make chronological. A manifest would also have to say what the label for each entry is, and that is a second place for the caller's own naming to live.
